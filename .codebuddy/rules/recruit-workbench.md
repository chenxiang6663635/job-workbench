# 秋招工作台项目规则

本仓库是 2027 届秋招工作台，不是软件项目。所有操作围绕 JD 解析、简历生成、投递追踪展开。

## 执行任何任务前必读

**先读 `CODEBUDDY.md`**——候选人档案、能力分层、硬门槛事实、经验资产、七条诚实红线。

不读该文件不得评分、不得改写简历、不得生成面试材料。

## 目录唯一事实源

`00_事实库/` 是全部事实的唯一来源。简历动词、行为故事、JD 评分的「经历匹配」维度都必须回查事实卡，**不得以其他文件的概述为准**。

## 七条诚实红线（强制，非建议）

1. 不认领 CNN 前端（前端由团队完成，个人负责后端控制、工况运行与结果分析）
2. X% 表述为「研究案例显示」，不得表述为工程实测结果
3. 不包装数据中心工程交付经验
4. 项目一只讲「已验证结论 vs 探索候选」，不称已部署
5. 项目二只说仿真与单一阅览室案例及 CO₂ 权衡，不称工程落地
6. 简历每个动词都要经得起 5–10 分钟追问，不把「参与」一律升级为「负责」
7. 知识缺口用诚实的桥梁回答，永不编造经历

## 硬门槛判定纪律

`CODEBUDDY.md` 第三节任一字段为 `[待填]` 时，一律按 **fail** 处理并提示用户补齐。

**禁止猜测，禁止按「可能满足」放行。**

## 工程约束

- Python 3.8.19 → 脚本禁用 3.9+ 语法（`dict | dict`、`list[str]` 等运行时注解）
- PDF 生成源是 HTML 模板，不是 Markdown。改简历内容必须同步更新 HTML
- 本仓库含姓名、照片与联系方式，且无远程备份 → **不得自动 `git commit`**，生成提交信息后交用户确认

## 文件组织纪律

- 新内容优先更新 `00_事实库/` 或现有主材料，不堆砌新的平行专题
- `tools/` 下脚本上限 5 个，互不调用。新需求优先改成工作流步骤，不要轻易新增脚本
- 改评分标准改 `config/` 与技能文件，不改代码
