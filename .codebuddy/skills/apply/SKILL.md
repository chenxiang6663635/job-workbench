# 生成投递包

**执行前必读**：`CODEBUDDY.md` 第四至六节（经验资产、七条诚实红线、简历版本与基线）与 `.codebuddy/skills/recruit-coach/SKILL.md`。

## 前置检查

读 `01_岗位池/<公司>_<岗位>/解析卡.md`。

- 不存在 → 提示先执行 JD 解析
- 「门槛结论」不是「通过」→ 终止，提示未通过硬门槛
- 总分低于 45 → 先向用户确认是否仍要投递，不直接生成材料

## 流程

### 1. 选定简历版本

| 方向 | Markdown 源 | HTML 模板 |
|---|---|---|
| datacenter | `02_简历工坊/简历_数据中心冷却版_v1.0.md` | `02_简历工坊/pdf/resume_datacenter.html` |
| hvac | `02_简历工坊/简历_HVAC空调制冷版_v1.0.md` | `02_简历工坊/pdf/resume_hvac.html` |

方向为 other 时按 JD 侧重点选更接近的一版，并在备注说明。

### 2. 按需微调简历

**只改四处**：求职方向、Profile、技能顺序、项目表述。**项目事实一律不动。**

每个动词都要经得起 5–10 分钟追问。动词由 `03_面试准备/项目表达/项目二/项目2贡献矩阵_待填.md` 的贡献矩阵决定，**不把「参与」一律升级为「负责」**。

改完**必须同步更新对应 HTML 模板**——HTML 是 PDF 的生成源，只改 md 不会反映到 PDF。

### 3. 生成 PDF 并 ATS 校验

```
python tools/resume_build.py --version <hvac|datacenter>
```

三项全过才算成功：页数为 1、可提取文本 ≥ 800 字符、`config/ats_required_facts.txt` 中 18 项关键事实全部命中。

**任一项不通过 → 中止，不归档、不写追踪表**，报告具体失败项。

超页时按序删减：驾驶证 → 本科 GPA/部分课程 → Profile 压一行 → 项目1方法细节 → 标准栏。**绝不先删**：X% 结果、控制贡献、SCI、硕士课程成绩、工程实践。

### 4. 归档

在 `05_投递追踪/applications/<公司>_<岗位>/` 下保存：

- `JD原文.md`：投递时的 JD 快照（能回答「三个月前投这家时 JD 怎么写的」）
- `简历_投递版_<YYYYMMDD>.pdf`：本次实际投递的版本（能回答「当时用的哪版简历」）
- `面试记录.md`：空白模板，含公司、岗位、轮次、日期、被问问题、答得不好的点

### 5. 写入追踪表

```
python tools/tracker.py add --company "<公司>" --role "<岗位>" \
    --direction <方向> --batch <批次> --source <来源> \
    --deadline <YYYY-MM-DD> --applied <YYYY-MM-DD> \
    --stage 已投 --resume <版本> --score <评分> \
    --archive "05_投递追踪/applications/<公司>_<岗位>"
```

取回 id，回填归档目录备注。

### 6. 提交

**不得自动执行 `git commit`。** 生成提交信息 `apply: <公司> <岗位>` 与待提交清单，交用户确认后由用户执行。

本仓库含姓名、照片与联系方式，且无远程备份，非预期提交难以撤回。

## 输出要求

报告：简历版本、PDF 路径、ATS 校验结果、归档目录、追踪表 id、待提交清单与建议的提交信息。
