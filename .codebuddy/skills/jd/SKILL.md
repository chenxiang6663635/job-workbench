# 解析 JD 并判定是否值得投递

**执行前必读**：`CODEBUDDY.md`（候选人档案、硬门槛事实、七条诚实红线）与 `.codebuddy/skills/recruit-coach/SKILL.md`（评分标准）。不读这两份文件不得开始评分。

## 流程

### 1. 建岗目录并存原文

在 `01_岗位池/` 下建 `<公司>_<岗位>/`，把 JD 原文完整落盘为 `JD原文.md`。

**保留原始文本，不改写、不摘要、不翻译。** 后续判断都要能回到原文核对。

只给岗位名没给 JD → 提示需要 JD 原文，不得凭岗位名臆测内容。

### 2. Eligibility Gate（硬门槛过滤）

顺序判定：学历 → 专业 → 届数 → 英语 → 城市。事实只从 `CODEBUDDY.md` 第三节取值。

**任一字段为 `[待填]` 时按 fail 处理**，输出：

```
无法完成硬门槛判定：CODEBUDDY.md 中「<字段名>」尚未填写。
请补齐后重新执行。
```

**禁止猜测，禁止按「可能满足」放行。**

任一项 fail → 解析卡只填「基本信息」与「硬门槛」两节，写明不通过原因，**终止流程**。不打分、不生成材料、不进入投递。

城市为 pass/fail 不参与加权。工作形态问题（长期驻场、倒班、长期出差）不在此判定，归入「培养与稳定性」扣分。

### 3. 生成解析卡

从 `01_岗位池/_模板_解析卡.md` 复制模板，填全部小节。方向未指定时由你依据 JD 判断并写明依据。

四维度打分：

- **技术匹配 30**：比对 `config/direction_<方向>.md` 三级词典。Primary 3 分/项、Secondary 1.5 分/项。命中 Weak 不扣分，但必须登记到「命中 Weak」并触发风险提示。
- **经历匹配 25**：逐条比对三条经验资产与 JD 职责，对上核心职责 8–10 分、侧面支撑 3–5 分、无关 0 分。**必须回查 `00_事实库/` 核验**，不得以概述为准。
- **方向契合 30**：按 `config/direction_<方向>.md` 锚点表取值。岗位名与职责不一致时以职责为准并说明依据。
- **培养与稳定性 15**：按 recruit-coach 的四分档判据取值。

评分依据要引用 JD 原文措辞与 `00_事实库/` 具体条目，不写空泛理由。

**不属于两个预设方向的岗位**：回退数据中心配置，并在解析卡末尾追加：

```
⚠️ 该岗位不属于两个预设方向，评分基于数据中心配置计算，结论仅供参考。
```

### 4. 校验并出结论

```
python tools/jd_score.py "01_岗位池/<公司>_<岗位>/解析卡.md"
```

校验失败（退出码非 0）→ 按脚本指出的字段修正后重跑，**不得跳过校验直接给结论**。

通过 → 把档位与下一步回填解析卡「结论」小节，并向用户输出：总分、四维度明细、档位、下一步、命中 Weak 项及诚实桥梁话术建议。

### 5. 桥梁话术的约束

命中 Weak 项时给出的建议，只能指向**真实可迁移能力**，并明确标注是知识性了解。**不得生成听起来像亲身经历的表述。**（七条诚实红线第 7 条）

## 输出要求

不复述 JD 内容。聚焦：判了什么、为什么这么判、下一步做什么。
