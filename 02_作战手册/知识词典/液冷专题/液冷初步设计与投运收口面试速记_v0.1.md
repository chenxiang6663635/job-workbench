# 液冷初步设计与投运收口面试速记_v0.1

> 定位：数据中心冷却主线 · 液冷学习收口课（从原理进入初步设计与投运）。
> 回链：承接 `液冷暖通工程核心面试速记_v0.1.md`（热平衡/水力/温度/自然冷却）、`液冷可靠性与故障域控制面试速记_v0.1.md`（可靠性/冗余/故障域）、`CDU六功能详解面试速记_v0.1.md`（CDU 六功能）、`空气与液体共同排热_液冷覆盖率面试速记_v0.1.md`（η_liquid）。
> 本篇不再扩展液冷路线，而是把已学的热平衡、水力、温度、可靠性和冗余整合成真实项目思路：先取 IT thermal-fluid envelope → 设计 TCS/CDU/FWS/冷源/空气侧/冗余 → 四维校核 → 投运五阶段。
> 核心：液冷基础设施不能从冷机或 CDU 名义容量反推服务器需求，而要先取得 IT 设备的热—流体边界条件。

## 三处必须校正的概念

### 校正1：CDU 不是"直接按 IT 总功率选"
正确关系：Q_IT ≠ Q_liquid。
对 1 MW IT 区域，若教学假设冷板捕获比例为 85%：Q_liquid = 1,000 × 85% = 850 kW；Q_air = 1,000 − 850 = 150 kW。
- 850 kW 是 CDU/TCS 需要承担的概念设计热负荷；
- 150 kW 是仍需由服务器风扇、机柜空气侧、CRAH/CRAC 等处理的残余热负荷。
实际项目中，液冷捕获比例必须以服务器/OEM 的热设计资料为准，不能假定所有 AI 服务器都是 85%。冷板液冷中，CPU/GPU 热量通常被 TCS 带走，但未覆盖部件仍需要空气侧冷却。（与 `空气与液体共同排热` 的 η_liquid 一致，此处落到设计计算。）

### 校正2：温度梯级的相对关系要画对
"芯片 → Cold Plate → TCS Return → TCS Supply → CDU → FWR → FWS"容易被误读成温度顺序。正确关系是温度通常从高到低：
```
芯片结温 > 冷板壁面温度 > TCS 回液温度 > TCS 供液温度 > FWS 供水温度
```
同时，设施水吸热后：FWS 供水 ↓ 经 CDU 换热器吸收 TCS 热量 → FWS 回水（带热）。
更完整：
```
TCS 回液（热）→ CDU 液—液换热器 → TCS 供液（冷却后）
FWS 供水（较冷）→ 同一个 CDU 换热器 → FWS 回水（带热）
```
关键约束：为了让热量从 TCS 传到 FWS，TCS 的温度必须比对应位置的 FWS 温度更高；换热器还需要保留逼近温差（approach）。不能设想 T_TCS,supply = T_FWS,supply 并同时要求有限面积的换热器传递大量热量。CDU 的作用正是让 TCS 与 FWS 隔离，并在两侧存在足够温差时传递热量。

### 校正3："单台 CDU 在线检修"不能只靠 N+1 名义
"CDU N+1 且单台在线检修"比普通 N+1 多了一层要求：可维护性（concurrent maintainability）。
例：正常需要两台 CDU 承载 850 kW，安装三台 CDU（CDU-1+CDU-2 正常运行，CDU-3 备用或分担运行）。当 CDU-1 检修时，要真正做到不中断关键服务器液冷，必须同时满足：
```
CDU-1 能被供回液阀隔离
   ↓
CDU-2 与 CDU-3 能接管对应液冷负荷
   ↓
剩余 CDU 的热容量、流量、扬程、压差均足够
   ↓
公共 TCS 主管、FWS 主管、供电、控制与通信未成为单点
   ↓
切换期间关键冷板流量与 TCS 供液温度不越限
```
所以，N+1 是容量条件；在线检修还需要隔离阀、旁通/备用路径、控制切换与真实验证。仅有"3 台 CDU"并不自动等于可在线维护。

## 概念设计计算题（1 MW 示例）
液冷承担 850 kW、近似使用水，取 c_p = 4.2 kJ/(kg·K)、ΔT = 8 K：
```
ṁ = Q/(c_p·ΔT) = 850/(4.2×8) ≈ 25.3 kg/s
V̇ ≈ 25.3 × 3.6 ≈ 91.1 m³/h（近似按水密度 1000 kg/m³）
```
结论：850 kW 液冷负荷、8 K 温差假设下，TCS 设计流量约 25.3 kg/s，即约 91 m³/h。该值只是概念设计估算；最终应以实际冷却液物性、冷板允许流量、设备允许温度、最不利支路压降和 OEM 热流体接口要求校核。

## CDU 选型四维校核（新增能力：不是背选型表）
| 校核维度 | 要问的问题 | 不能只看什么 |
|---|---|---|
| 热容量 | CDU 换热器能否持续传递 850 kW 热量？ | 不能只看铭牌峰值 kW |
| TCS 流量 | 是否能提供约 91 m³/h 的设计流量？ | 不能只看泵台数 |
| 水力能力 | 最不利冷板支路是否仍有足够流量、压差和控制余量？ | 不能只看 CDU 出口总压差 |
| 可靠性 | 一台 CDU 退出后，剩余系统能否同时满足热量、流量、压差和温度？ | 不能只说"N+1" |

CDU 的热交换能力、TCS 流量与压力控制、设备级温度要求和设施水条件必须一起校核；液冷系统不能以统一的水温、流量或过滤等级替代不同 OEM 的热流体接口条件。

## IT Thermal-Fluid Envelope（IT 设备热—流体边界条件）
这是今天最值得写进笔记的一张表：
| 需要从 IT/OEM 获取的条件 | 暖通/液冷设计为什么需要 |
|---|---|
| 最大 IT 功率、峰值功率与增长计划 | 确定总负荷、液冷负荷与扩容策略 |
| 液冷覆盖比例 | 拆分 TCS/CDU 容量与空气侧残余冷量 |
| TCS 允许供液温度范围 | 确定 CDU、FWS、自然冷却与结露边界 |
| 最大回液温度 | 校核 TCS 温差与芯片热安全 |
| 每台服务器/冷板设计流量 | 确定机柜歧管、支路与 CDU 流量 |
| 冷板允许压降 | 确定泵扬程、最不利环路与压差控制 |
| 冷却液类型与水质规范 | 确定材料、过滤、补液、水处理和维护 |
| 最大工作压力 | 校核软管、快接头、歧管、阀门和 CDU |
| 漏液告警与保护要求 | 设计传感、隔离、联锁、IT 降载与 SOP |
| 冗余与维护要求 | 决定 CDU、泵、TCS/FWS 管网和控制架构 |

面试表达：液冷基础设施不能从冷机或 CDU 名义容量反推服务器需求，而要先取得 IT 设备的 thermal-fluid envelope，包括功率、液冷捕获比例、供回液温度、流量、允许压降、压力、水质、冷却液和保护要求；之后才设计 TCS、CDU、FWS、冷源、残余空气侧与冗余策略。

## 调试投运顺序（压缩为五个阶段）
```
1. 机械完整性：管路、阀门、支撑、快接、保温、标签与排水检查
2. 液体准备：冲洗、过滤、注液、排气、水质确认
3. 控制与单机：传感器校验、泵阀单机、CDU 温度/压差控制测试
4. 系统平衡：最不利支路流量、压差、温度与机柜歧管平衡
5. 带负荷与故障验证：实际 IT 热负荷、泵切换、CDU 退出、FWS 失流、传感器异常、漏液和通信异常测试
```
启动阶段尤其要重视施工残留、排气、过滤器压差、水质、支路平衡和传感器校准。水基 TCS 的部署指导也强调初始冲洗、过滤、液体管理、材料兼容性和持续水质维护的重要性。

## 大题推荐答案（1 MW AI 计算区）
对于 1 MW AI 计算区，我首先不直接按 1 MW 配 CDU，而是确认服务器液冷覆盖比例。按题设 85% 由冷板液冷承担，则 TCS/CDU 设计热负荷约为 850 kW，剩余 150 kW 仍需由服务器风扇、机柜气流组织和 CRAH 等空气侧处理。

其次，根据 Q=ṁc_pΔT，按水的比热 4.2 kJ/(kg·K)、TCS 温差 8 K 估算，850 kW 对应流量约为 25.3 kg/s，即约 91 m³/h。这个结果只作为概念设计值，后续还要依据实际冷却液物性、服务器和冷板允许流量、回液温度限制及最不利支路压降校核。

CDU 选型不能只看 850 kW 热容量，还要同步验证换热器能力、TCS 设计流量、最不利冷板环路的扬程和压差，以及 TCS 供液温度控制能力。设施侧还要确认 FWS/FWR 温度、CDU 逼近温差、FWS 流量、冷源容量、自然冷却窗口和室外工况。

冗余方面，若正常需要两台 CDU，应采用第三台作为 N+1 容量，并验证任一 CDU 退出后，剩余两台仍能提供 850 kW、91 m³/h、最不利支路所需压差和目标 TCS 供液温度。若要求在线检修，还要有可隔离阀门、备用路径、自动切换逻辑及无公共单点的 TCS/FWS、供电和控制架构。

最后，设计完成不代表可运行。投运时还应完成冲洗、过滤、注液、排气、水质确认、传感器校验、流量平衡、带负荷测试和 CDU/泵故障切换测试，证明正常工况与故障工况下都存在完整、可控的排热路径。
