## 模块1：热平衡与流量计算
公式 Q=ṁc_pΔT，因此 ṁ=Q/(c_p·ΔT)，其中 Q 为 TCS 回路实际带走热量，ṁ 为技术冷却液质量流量，c_p 为冷却液比热容，ΔT=T_return−T_supply 为 TCS 供回液温差。

例题：Q=200 kW，c_p=4.2 kJ/(kg·K)
| TCS 供回液温差 ΔT | 所需质量流量 ṁ | 近似体积流量（水） |
|---|---|---|
| 5 K | 9.52 kg/s | 34.3 m³/h |
| 8 K | 5.95 kg/s | 21.4 m³/h |
| 10 K | 4.76 kg/s | 17.1 m³/h |

示例计算（ΔT=5 K）：ṁ = 200/(4.2×5) = 9.52 kg/s。

工程结论：热负荷固定时，把 TCS 温差从 5 K 提高到 10 K，理论所需质量流量约减半，泵送流量、管径需求和输配能耗都有降低空间；但温差不能无限增大，因为回液温度和冷板局部温度会上升，远端支路热风险也会增加。最终温差应由服务器/冷板厂商的允许供回液温度、最低流量、压降、支路平衡与 CDU 工作范围共同决定，而不是只追求最小泵耗。

把"水"当近似冷却液来算是可以的；实际系统若采用加了乙二醇或其他配方的冷却液，应使用对应的比热和密度，不要机械沿用 4.2 kJ/(kg·K)。

## 模块2：压降、压差与 CDU 泵
阻力链：CDU 泵 → TCS 主管 → 机柜歧管 → 服务器软管与快速接头 → 冷板 → 回液歧管与回水管 → CDU。其中冷板、快速接头、过滤器、阀门、歧管、软管、弯头和换热器都会产生压降。CDU 泵的目标不是"最大流量"，而是在最低合理泵耗下，使最不利服务器支路和最不利冷板仍获得其要求的流量。

远端为什么更容易缺流：近端服务器 CDU → 短管路 → 较小压降 → 容易获得流量；远端服务器 CDU → 更长管路/更多接头/更多局部阻力 → 压降更大 → 更容易流量不足。

CDU 不应只看总流量，还应看：TCS 总供回液压差；最不利机柜或支路压差；关键支路流量；冷板供回液温差；GPU/服务器温度；泵频率、泵功率和泵状态；过滤器压差与阀门状态。

两种泵控制逻辑：
| 控制方式 | 做法 | 优点 | 局限 |
|---|---|---|---|
| 恒压差控制 | CDU 持续维持固定 TCS 供回液压差 | 简单，能保证基础供液能力 | 低负荷时压差可能偏高，泵耗和节流增加 |
| 压差重置 | 根据最不利支路、阀位、支路流量、IT 负荷动态调整目标压差 | 更贴近实际需求，节能潜力更高 | 需要可靠测点、逻辑和安全回退策略 |

与既有暖通知识的连接：CDU 泵的压差重置，与冷冻水泵的差压重置本质相同——不要让系统长期维持高压差，而是以最不利末端需求为约束，在确保关键冷板流量的前提下降低泵速和泵耗。不同之处是液冷支路更贴近 IT 设备，且快接头、冷板和软管的压力/流量边界更严格。

CDU 泵的正确闭环：
```
IT 功率上升 / GPU 温度趋势上升
        ↓
TCS 回液温度上升、温差变化
关键支路流量或压差接近下限
        ↓
CDU 判断：是否需要提高输送能力？
        ↓
提高 CDU 泵频率 / 压差设定值
必要时调节支路阀或 FWS 换热能力
        ↓
TCS 流量与压差恢复
冷板带热能力提高
        ↓
反馈：GPU温度、TCS温差、支路流量、压差、泵耗
```
"GPU 越热 → 泵直接全速"是错误示例（判断正确）。

泵速增加不能解决所有温度问题：
| 现象 | 可能原因 | 首选判断 |
|---|---|---|
| TCS 流量低、压差低、GPU 温度高 | 泵速不足、过滤器堵塞、支路阀异常、气堵 | 优先检查水力输配 |
| 流量正常但 TCS 供液温度偏高 | FWS 温度过高、CDU 换热不足、设施侧流量不足 | 优先检查 CDU/FWS/冷源 |
| TCS 温度和流量正常但 GPU 温度高 | 冷板接触、芯片负荷、服务器内部问题 | 不能盲目加泵 |
| 单支路温度异常 | 歧管、快接头、阀门或冷板局部问题 | 查看支路压差、流量和设备状态 |

## 模块3：TCS 供液温度与露点
CDU 的 TCS 供液温度控制目标：满足 IT 设备和冷板的温度要求，同时保持稳定、避免过冷、避免结露，并尽量为高温设施水和自然冷却创造条件。

CDU 如何调温：
```
TCS 供液温度偏高
        ↓
增加 CDU 换热量
        ↓
增加 FWS 通过 CDU 换热器的流量
或降低 FWS 入口温度
        ↓
TCS 供液温度下降
```
不同 CDU 可能通过 FWS 调节阀、混水阀、TCS 旁通、泵速、换热器控制及上游冷源设定协同实现；不要把某一种阀门布置说成所有 CDU 的固定结构。

露点判断：T_surface < T_dew point ⇒ 可能结露。液冷系统中，冷板附近外露管路、软管、快接头、歧管、阀组和 CDU 的低温表面都可能成为结露位置。TCS 供液温度若低于周围空气露点，就可能使水汽凝结在这些表面，威胁电子设备可靠性。

面试最稳说法：冷板液冷不能只追求最低供液温度。TCS 供液温度要同时满足芯片散热和环境露点约束；若冷却液温度低于周围空气露点，软管、接头、歧管或冷板附近可能结露。工程上通常会以实时或设计露点为基准设置一定温度安全裕量，并在湿度异常、传感器失效或低温冷源切换时采取保守控制。

不要死背"永远高于露点 2°C"这种通用数值；2°C 是工程中常见的裕量示例，但实际值应遵循设备制造商要求、保温措施、传感误差、控制精度和现场湿度管理策略。

## 模块4：FWS 接入与自然冷却
热量路径：TCS → CDU 换热器 → FWS/FWR → 冷源或自然冷却设备 → 室外环境。注意：冷水机、干冷器、冷却塔和板换并不意味着一定全部串联运行；它们可能是不同方案或不同运行模式中的组件。

| 模式 | 主要热量路径 | 适用情况 | 能耗特点 |
|---|---|---|---|
| 机械制冷 | FWS → 冷水机 → 冷却水/冷却塔 → 室外 | 高室外温度、所需 FWS 温度较低、自然冷却不足 | 压缩机能耗较高 |
| 自然冷却 | FWS → 板换/干冷器/冷却塔等 → 室外 | 室外条件与换热温差允许 | 可部分或完全绕过压缩机 |
| 混合运行 | 自然冷却承担部分负荷，冷机补足 | 过渡季、部分负荷或室外条件变化 | 追求系统总功率更低 |

三种典型排热路线（FWS 侧具体展开）：
1. 冷水机 + 冷却塔：
```
CDU → FWS 带热回水 → 冷水机蒸发器 → 制冷剂 → 冷凝器 → 冷却水泵 → 冷却塔 → 室外环境
```
适合室外温度高、自然冷却条件不够、或需要较低 FWS 温度时；缺点是压缩机耗电，冷机能耗通常较高。这是最熟悉的传统 HVAC 冷水机组逻辑。
2. 干冷器自然冷却：
```
CDU → FWS 带热回水 → 干冷器盘管 → 室外空气
```
干冷器像大型室外盘管加风机，不依赖冷机压缩机，室外空气足够冷时可直接排热。高温液冷更容易用：若 TCS/FWS 允许更高温度，就更容易与室外空气形成足够换热温差。
3. 板换/冷却塔自然冷却或混合模式：
```
CDU → FWS → 板式换热器 → 冷却水/冷却塔侧 → 室外环境
```
条件较好时板换和冷却塔可承担部分或全部排热；条件不够时冷水机补足剩余冷量。现实系统常是"自然冷却 + 机械制冷"的混合运行，而非只有冷机开/关两种状态。

为什么液冷可能更利于自然冷却：不是"液冷天然不需要冷机"，而是——若 IT 设备允许较高 TCS 供液温度 → CDU 所需 FWS 温度也可能提高 → 与室外空气/湿球温度之间的可用换热温差增大 → 干冷器、冷却塔、板换等自然冷却可用时间可能增加 → 压缩机运行时间和冷机负荷可能下降。

但最终是否能实现部分或全自然冷却，仍取决于：TCS 与 FWS 允许温度；CDU 换热器逼近温差；室外干球/湿球气象条件；干冷器、冷却塔、板换能力；水泵与风机功耗；露点和结露控制；冗余与故障工况。因此应说"可能扩大自然冷却窗口"，而不要说"液冷一定可以不用冷机"。

## 模块5：五类故障（故障—后果—第一保护框架）
| 故障 | 直接后果 | 第一保护与排查重点 |
|---|---|---|
| CDU 泵故障 | TCS 流量下降或中断，芯片温度可能快速上升 | 冗余泵/N+1、自动切换、失流告警、IT 限功率或保护 |
| 过滤器堵塞 | 压降上升，远端或关键支路缺流 | 过滤器差压监测、维护更换、检查水质 |
| 支路堵塞/快接头异常 | 单台服务器或单组 GPU 流量不足 | 支路流量/压差监测、分区隔离、维护 |
| 漏液 | 液体损失、设备与安全风险 | 漏液检测、隔离阀、告警、停泵或受控降级 |
| FWS/冷源中断 | CDU 无法持续将 TCS 热量排出 | 冗余设施水路径、备用冷源、负荷降载、IT 保护策略 |

这与已掌握的数据中心冷却冗余完全一致：关键不是"有没有一台备用泵"，而是故障后是否仍有一条可供电、可控制、可隔离、能持续排热的完整路径。

## 模块6：项目迁移（各 30 秒，今日定稿）
项目一（30秒）：我的主课题研究传感数据缺失条件下模型性能如何退化，以及能否通过缺失感知训练和关键变量筛选提高预测稳定性。液冷 CDU 系统依赖 TCS 供回液温度、流量、压差、泵频率、阀位、IT 功率和 FWS 温度等数据；如果某个流量或压差传感器失效，就可能影响热风险判断和泵控策略。我的方法可以迁移到液冷的软测量和传感器缺失鲁棒性研究，例如利用温度、泵频率、相邻支路状态与 IT 功率共同估计当前热状态。但这目前是方法迁移设想，尚未使用液冷真实数据验证。

项目二（30秒）：项目二体现的是按实际需求动态调节 HVAC 输出的闭环：感知人数，计算新风需求，调节 DOAS 阀门，再用能耗和室内环境反馈验证。CDU 控制可类比为依据 IT 负荷、TCS 温度和支路状态判断冷却需求，调节 CDU 泵频率和设施水侧阀门，再用芯片温度、供回液温差、流量、压差与能耗反馈校验。区别在于建筑项目优先平衡舒适和 IAQ，而液冷系统必须首先满足芯片热安全、露点、最小流量、泄漏保护和连续运行约束。
