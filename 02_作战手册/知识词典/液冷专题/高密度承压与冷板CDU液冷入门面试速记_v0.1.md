# 高密度承压与冷板-CDU液冷入门面试速记_v0.1

> 定位：数据中心冷却主线 · 高密度与液冷边界专题。
> 回链：与 `数据中心冷却面试速记`、`PUE理解与冷却能耗链面试速记`、`CRAH风机与冷冻水泵变频节能面试速记`、`设定值优化面试速记`、`冷冻水冷却水系统与水泵控制面试速记` 平行，不重复。
> 本篇只建立"高密度为什么推高液冷需求"的因果链，以及"冷板/CDU 系统边界"的入门框架；不进入冷板流道、翅片、TIM、封装结构等细节。

## 模块A：高密度如何承压

### 核心立场（先别背绝对阈值）
不要先背"超过多少 kW/柜就必须液冷"的绝对阈值。是否采用液冷，受服务器设计、热负荷分布、机房结构、环境条件、经济性及可靠性目标共同影响。可以确定的是：高密度 AI/HPC 场景显著提高了采用液冷或风液混合冷却的需求，但它是多因素决策，不是单一功率门槛触发。

### 一条因果链
```
AI训练 / HPC计算
  ↓
GPU、CPU等芯片功耗与局部热流密度上升
  ↓
单柜热负荷更集中、波动更快
  ↓
若继续主要依赖空气带热：
需要更大有效风量
  ↓
风机功率、压降、噪声、气流组织难度上升
  ↓
冷风旁通与热空气回流的风险增大
  ↓
高负荷机柜进风/芯片温度裕量缩小
  ↓
评估近端空气冷却、后门换热器或冷板液冷
```

### 空气侧热平衡仍然成立
Q = ρ·V̇·c_p·ΔT

当 Q 上升时，若送回风温差不能无限扩大，就必须增加有效空气流量 V̇。但实际机房中风量不能无限增加：风机耗电大致随转速立方变化（相似定律 P∝n³）、架空地板和风道压降增加、漏风与旁通增多，而热空气回流会使服务器实际吸入的空气越来越热。这正是高密度把空气侧推向极限的物理原因。

### 风液混合不是过渡失败
冷板液冷不等于"机房不再需要 CRAH"。典型直接芯片液冷（D2C/DLC）系统中，热量按来源分流：

| 热负荷来源 | 主要冷却路径 |
|---|---|
| CPU、GPU、AI 加速器等高热流密度部件 | 冷板 → 技术冷却液 → CDU → 设施水/冷源 |
| 内存、网卡、存储、电源、主板及其他残余热量 | 服务器风扇 → 机柜空气侧 → CRAH/CRAC |
| 机柜内与机房内剩余混合热量 | 冷热通道与空气处理系统 |

正确表达：液冷的价值是把高热流密度芯片的主要热量在服务器近端由液体带走，降低空气侧承担的比例与局部风量压力；但在多数冷板液冷架构中，空气侧仍需处理未覆盖部件和残余热量，因此风液混合会长期存在。这与 `CRAH风机与冷冻水泵变频节能面试速记` 中"CRAH 仍然承担空气侧残余负荷"的框架一致。

## 模块B：冷板与CDU入门

> 本模块只建立"系统边界"，不进入冷板的流道、翅片、TIM 或封装结构。

### 四个术语
| 术语 | 你需要掌握的定义 |
|---|---|
| 冷板（Cold Plate） | 紧贴 CPU/GPU 等主要发热件的液体换热部件，冷却液在其中流动，将芯片热量带走 |
| D2C/DLC | Direct-to-Chip / Direct Liquid Cooling，直接把冷却液送到芯片冷板的典型液冷路线 |
| TCS | Technology Cooling System，服务器侧技术冷却回路，连接冷板、机柜歧管和 CDU 二次侧 |
| FWS | Facility Water System，设施侧水回路，将 CDU 接出的热量送向冷机、冷却塔、干冷器或其他室外排热系统 |
| CDU | Coolant Distribution Unit，连接 TCS 与 FWS 的设备单元，通常通过换热器实现两回路隔离，并承担二次侧泵送、监测、控制等功能 |

OCP 的液冷参考资料将 FWS 定义为把热量从 CDU 输送到设施冷却基础设施的回路；CDU 则为 IT 设备提供隔离的冷却回路。其设施冷却基础设施可包括冷水机、冷却塔、经济器和蒸发冷却设备。

### 一张必须能画的图（系统边界）
```
                 服务器侧：TCS
CPU / GPU
  ↓ 发热
冷板
  ↓ 技术冷却液
机柜歧管 / 服务器支路
  ↓
CDU 二次侧泵、过滤、监测
  ↓
CDU 换热器
  ↓
                 设施侧：FWS
冷水机组 / 干冷器 / 冷却塔等冷源
  ↓
室外环境
```

更完整地表示供回路：
```
TCS供液 → 冷板 → TCS回液 → CDU
                         ↓ 换热器
FWS供水 → CDU → FWS回水 → 冷源与室外排热
```
两个回路通常不直接混水。这样可隔离服务器侧与设施侧的压力、水质和温度控制要求；CDU 在中间通过换热器传递热量，并使服务器侧技术冷却液保持在受控状态。该边界与 `冷冻水冷却水系统与水泵控制面试速记` 中"设施侧冷冻水/冷却水"的主线衔接：FWS 二次侧最终仍是接冷机或干冷器/冷却塔排热。

### CDU必须讲出的六类功能（面试精炼版，逐功能详解见 `CDU六功能详解面试速记_v0.1.md`）
1. 换热与隔离：通过液—液换热器把 TCS 热量传给 FWS，两侧液体通常不直接混合，隔离压力、水质、污染物和运行边界。
2. 泵送与分配：内置泵推动技术冷却液通过冷板、软管、快接头和歧管，克服流阻，让远端服务器也得到足够流量。
3. 温度控制：调节设施水阀、旁通/混水、泵速与换热量，维持 TCS 供液温度并避免过冷、过热与结露。
4. 压力与压差控制：控制 TCS 供回液压力、压差和支路流量，防止远端流量不足、过流、接头压力过高。
5. 液体质量管理：过滤、补液、液位、水质/污染状态管理，防止冷板微通道堵塞、腐蚀或性能衰减。
6. 监测与保护：监测温度、流量、压差、阀位、泵、过滤器、漏液、通信并告警，提前发现风险，联锁、降级或切换保护 IT 设备。

暂时不需要记某厂商 CDU 的具体型号、精确过滤精度或特定接口协议。先讲清楚它为什么存在：CDU 是 IT 侧技术冷却回路和设施水/冷源系统之间的"隔离、换热、泵送与控制接口"，也是把换热、泵送、温压流量控制、监测和保护集成在一起的液冷基础设施设备（不是单个板式换热器）。

## 笔记版要点（自测清单）
- 高密度推高液冷需求是"多因素决策"，不是绝对 kW/柜阈值。
- 空气侧热平衡 Q=ρV̇c_pΔT：Q 升、ΔT 不能无限扩 → 必须加风量；但风机 P∝n³，且旁通/回流使进风变热。
- 风液混合长期存在：冷板只覆盖 CPU/GPU 等高热流密度件，内存/电源/网卡仍走 CRAH 空气侧。
- 五术语：冷板、D2C/DLC、TCS、FWS、CDU；能画出 TCS↔CDU换热器↔FWS 的供回液图。
- CDU 六功能：隔离换热、二次侧泵送、流量压差控制、温度控制、过滤液体管理、监测告警冗余。

## 90秒口述稿（今日工程输出）
普通数据中心主要通过服务器风机、冷热通道和 CRAH/CRAC 将 IT 热量带入空气侧，再经冷冻水、冷机和冷却塔或干冷器排到室外。但 AI/HPC 场景中，GPU 和 CPU 使单柜热负荷及局部热流密度上升。若继续主要依靠空气冷却，根据 Q=ρV̇c_pΔT，就需要更大的有效风量；这会增加风机能耗、压降、旁通和热空气回流风险，因此局部热点和气流组织压力更突出。

冷板液冷并不是直接替代整个机房空气系统，而是把 CPU/GPU 的主要热量在服务器近端通过冷板和技术冷却液带走。技术冷却回路经过 CDU，通过换热器把热量传给设施水回路，最终仍由冷机、干冷器或冷却塔排到室外。CDU 的关键角色是隔离服务器侧与设施侧回路，并提供二次侧泵送、监测、过滤和控制。未被冷板覆盖的内存、电源和网络设备仍需要 CRAH/CRAC 处理，因此典型 AI 数据中心更常见风液混合冷却。
