## 三、项目一面试框架(缺失鲁棒 + 轻量化)

### 3.1 定位(收紧版口径)
> **面向建筑环境传感数据缺失的实际应用场景，研究热舒适预测模型的缺失鲁棒性与轻量化部署可行性。**
> 当前阶段产出为**建模思路与候选方案**:在传感器缺失场景下评估模型鲁棒性,并**探索**减少输入变量/传感器依赖的**可行性**(须经少参数模型重训练与复测验证)。

- 简历标题(定稿版,2026-08-17 冻结):**面向传感器缺失与传感器依赖的个体热舒适预测鲁棒性研究**("轻量化"只作研究动机与后续路径留在追问)
- 面试解释(工程版):面向建筑环境传感数据缺失实际场景的缺失鲁棒与轻量化热舒适预测研究

### 3.2 三段式结构
1. **建模基础**:基于热舒适数据库/实验数据,用 Python、XGBoost 完成预处理、训练与性能评估。
2. **缺失鲁棒性**:模拟空气温度、平均辐射温度、相对湿度、风速等关键传感器缺失,比较不同缺失处理策略与场景下的表现(A0–A3)。
3. **轻量化工程(探索可行性)**:在鲁棒性与变量敏感性/解释结果基础上,**提出少变量候选组合**,并**通过少参数模型重训练与复测**评估其在性能/鲁棒性/传感器成本间的可行性——不宣称已替代完整输入。

### 3.3 30 秒版
> 我的主课题是面向 HVAC 控制前端的轻量化与缺失鲁棒热舒适预测。实际建筑或设备运行中,传感器可能出现缺失、故障或配置不足,如果模型依赖过多传感器,会增加部署成本和运行风险。所以我基于 Python 和 XGBoost 等方法,一方面评估温度、湿度、风速等关键变量缺失时模型性能如何退化,另一方面分析不同变量对预测的贡献,**探索**在减少输入变量或传感器依赖的情况下,模型是否仍能保持较好性能,从而为 HVAC 控制前端轻量化状态估计**提供建模思路与候选方案**。

### 3.4 3 分钟版(6 步)
1. **背景**:热舒适预测用于 HVAC 控制前端时,不能只在完整数据上表现好。工程里两个问题:①传感器可能缺失/故障;②模型需要太多输入会增加配置成本与部署复杂度。
2. **目标**:不是单纯追最高准确率,而是回答两点——传感器缺失时是否鲁棒;减少输入变量/传感器依赖时是否仍可接受。
3. **方法**:Python 构建机器学习实验流程,XGBoost 做热舒适分类;设计完整数据、测试端缺失、训练端缺失暴露等场景,比较不同缺失变量/缺失率下性能;结合变量敏感性与模型解释分析关键传感器变量。
4. **缺失鲁棒性**:看空气温度/平均辐射温度/相对湿度/风速缺失时 macro-F1 等指标变化;A1 vs A2 对比可判断部署端退化与训练暴露缺失后的恢复效果。
5. **轻量化(探索可行性)**:在敏感性/特征重要性基础上提出少变量候选组合,**重训练少参数模型并复测**,在性能、鲁棒性、传感器成本间做工程权衡——这是"探索",非"已替代"。
6. **工程意义**:可迁移到设备运行监测、舒适性预测、冷却系统控制前端或智能运维场景,**当前以提供建模思路/候选方案为主**。

### 3.5 12 问
- **Q1 解决什么问题?** 两个:传感器缺失下的预测可靠性;减少传感器依赖后的轻量化部署可行性。
- **Q2 为何要考虑传感器缺失?** 实际系统温湿度/风速/辐射温度等传感器可能故障、通信中断或维护不足;只在完整数据训练的模型部署时可能明显退化。
- **Q3 为何还要考虑轻量化?** 工程部署中传感器越多,成本、布点、维护难度与缺失风险越高;用较少关键变量达接近效果更适合实际接入。
- **Q4 输入变量有哪些?** 空气温度、平均辐射温度、相对湿度、风速等环境变量(可能含个人/场景变量);面试强调环境传感器变量。
- **Q5 输出是什么?** 热舒适/热感觉分类,分类任务,用 macro-F1 等评价。
- **Q6 A0/A1/A2/A3?** A0 完整数据基线;A1 部署端缺失观察退化;A2 训练端暴露缺失后观察恢复;A3 检查缺失训练是否损害完整数据表现。
- **Q7 为何 XGBoost?** 适合结构化表格数据,捕捉非线性与变量交互;训练效率高,适合大量缺失场景实验;对缺失值有一定原生处理机制。
- **Q8 缺失处理方法?** XGBoost 原生处理、KNN、Iterative imputation 等;重点是比较不同 handler 在相同缺失条件下的鲁棒性差异,而非背方法名。
- **Q9 怎么判断变量重要?** SHAP/特征重要性只用于**识别候选关键变量**,不能直接等价于"该变量可删/可留";可辅以变量缺失敏感性,但 SHAP ≠ 因果。
- **Q10 轻量化怎么做(收紧)?** 不是简单删变量:①基于敏感性提出少变量候选组合;②**重训练少参数模型并复测**,在性能/鲁棒性/传感器成本间评估**可行性**。任何"已完成轻量化替代"的说法收回为"正在探索可行性"。
- **Q11 与数据中心关系?** 数据中心冷却依赖大量温湿度/流量/压力/功率传感器;本项目缺失处理、鲁棒性评估、轻量化输入思路可迁移到热管理监测与智能运维。
- **Q12 与空调制冷关系?** 空调系统也有大量运行数据与传感器(温度/湿度/流量/压力/阀门开度/功率);项目体现用数据分析处理运行数据、识别关键变量并支持系统优化的能力。

### 3.6 四个卖点
1. **懂建筑环境数据**:围绕热舒适、温度、湿度、风速、辐射温度等暖通变量建模,非随便跑公开数据。
2. **懂传感器缺失问题**:考虑真实工程里传感器缺失/故障/数据不完整。
3. **懂模型鲁棒性**:不只看 clean test 高分,看异常/缺失场景能否稳定。
4. **懂轻量化部署(探索级)**:关心减少输入变量与传感器依赖以降低工程成本,但定位为探索可行性与候选方案。

### 3.7 边界约束(必须守住)
- ✅ 探索轻量化输入方案 / 关注减少传感器依赖 / 分析关键变量与缺失影响 / 提供建模思路或候选方案
- ❌ 已部署到 HVAC 控制系统 / 已完成实际工程应用 / 已证明少量传感器完全替代完整输入 / 已形成成熟产品级方案
- SHAP 仅作解释补充,**不等同因果**;轻量化结论**须经少参数模型重训练与复测验证**。
