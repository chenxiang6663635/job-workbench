# 行为面专卡：三个项目里印象最深的问题与解决（STAR 定稿）

> 高频题："你在项目里有没有印象深刻的东西/问题？你是怎么解决的？"
> 面试官想看的不是"项目很难"，而是你有一套稳定的问题解决方式：**发现问题 → 判断原因 → 采取行动 → 验证结果 → 复盘边界**。
> 三个项目各绑一种能力，三条不重复；主答 = 项目二（CO₂ 冲突）。

## 三故事能力映射（记忆锚点）

| 经历 | 印象深刻的问题 | 主要证明什么 | 讲述要点 |
|---|---|---|---|
| 项目一（传感缺失） | 完整数据模型遇到缺失后性能退化 | 实验设计、鲁棒性思维 | 重新设计对照实验、验证鲁棒性 |
| 项目二（占控 HVAC）★主答 | 节能提高但 CO₂ 升高 | 系统权衡、控制思维 | 找到机制、明确局限、提出改进方案 |
| 某商业综合体实习 | 图纸系统到现场受空间/专业交叉约束 | 工程落地、现场意识 | 图纸理解、主动核对、不装懂 |

## ★主答：项目二 CO₂ 冲突（完整 STAR + 技术反思）

> 三个经历里我印象最深的是项目二，因为它让我第一次很直观地看到系统优化中的多目标冲突。

- **Situation**：占用驱动控制显著减少过度通风。
- **Task**：我负责控制逻辑、风量计算和仿真工况运行与结果分析。
- **Action**：比较 CCS/OBCS 工况 → 查看能耗 / PPD / CO₂ 结果 → 定位到单一 occupancy 前馈控制缺少 IAQ 闭环反馈。
- **Result**：节能 X%、PPD 改善，但 CO₂ 峰值近 1200 ppm；论文明确将其作为局限，提出后续 "occupancy + CO₂ feedback" 混合控制（人数前馈估算需求 + CO₂ 反馈修正）。
- **Reflection**：不能只优化能耗，控制系统要同时满足安全 / 舒适 / IAQ 约束。

**完整口述版（用户定稿，可背）**：
> 项目二里我印象最深的反而不是 X% 的节能结果，而是我们在分析 CFD 结果时发现，占用驱动控制虽然显著降低了新风处理能耗，而且平均 PPD 也有所改善，但部分区域的 CO₂ 浓度升高，峰值接近 1200 ppm。
> 我主要负责后端控制策略、风量计算以及 EnergyPlus 和 CFD 工况运行与结果分析，所以这个问题是在我整理不同工况结果时比较明显地暴露出来的。我们进一步分析后发现，原来的控制逻辑主要根据人数计算最小新风需求，它解决了过度通风，但没有把 CO₂ 浓度作为闭环反馈变量，所以节能和 IAQ 之间出现了冲突。
> 这个项目里我们没有把这个问题包装成"已经解决"。论文里把它明确作为局限，并提出后续可以采用"occupancy + CO₂ feedback"的混合控制，也就是人数用于前馈估算需求，CO₂ 用于反馈修正。
> 这件事让我真正理解到，HVAC 控制不能只优化单一指标，实际系统往往需要同时考虑能耗、舒适性和空气品质。

**关键纪律**：不要说"最后我解决了 CO₂ 问题"——你们没有真正做完混合控制验证。正确表达是"发现问题 → 找到机制 → 明确局限 → 提出可执行改进方案"。

## 备答一：项目一传感缺失（科研方法与鲁棒性）

> 我硕士课题里印象比较深的是，模型在完整数据条件下表现还可以，但一旦模拟实际传感器缺失，性能会出现明显退化。这个问题让我意识到，如果只在完整数据上训练和评估，其实不能说明模型具备真实部署能力。
> 后来我没有只换一个算法，而是重新设计了对照实验，把完整基线、部署端缺失、缺失感知训练和安全检查分开，同时比较多种缺失处理策略，并在不同缺失率和多次随机重复下验证结果。最后发现，缺失感知训练能够恢复部分性能，但不同处理策略之间存在鲁棒性权衡。
> 这件事对我影响比较大，因为我后来会更关注"模型在非理想条件下还能不能工作"，而不是只看一个最优指标。

**核心标签**：发现隐藏问题 → 重新设计实验 → 验证鲁棒性。
**追问"你到底解决了吗"**："没有把传感器缺失彻底消除，而是把原来模糊的问题转化成可以量化比较的实验体系，并验证了哪些策略能改善、改善到什么程度。"（比"我把模型调好了"成熟）

## 备答二：某商业综合体实习（图纸 vs 现场）

> 在某商业综合体中心改造项目里，我印象比较深的是风管、水管和机电桥架同时在既有建筑空间内施工。学校里看暖通图时，更多关注系统怎么连接，但到了现场以后，我发现真正安装时还要考虑梁、柱、原有结构、设备运输空间以及不同专业管线的标高。
> 我当时主要做的是结合施工图和现场反复核对设备、风管和水管的位置，同时跟进风管、水管防腐和桥架等施工。遇到图纸和现场不容易直接对应的地方，我会先按系统图确认管线属于哪一侧、连接什么设备，再结合现场位置去核对，并向现场师傅或技术人员确认。
> 这段经历让我对"设计正确"和"工程能够落地"之间的区别有了比较直观的认识。后来我学习冷水系统时，也会主动考虑设备布置、管线空间、检修和施工顺序，而不是只看理论参数。

**核心标签**：工程现场意识 + 图纸理解 + 主动确认 + 不装懂。**不硬编**"我发现重大管线冲突并独立解决"。

## 三种合格结果原则（HR 问"怎么解决的"时）

工程和科研里有三种完全合格的结果，不要强迫每个故事都是"我成功解决了"：
1. 真正解决；
2. 改善但没有完全解决；
3. 定位问题、明确边界并提出下一步方案。
项目二就是第三种。能清楚说"这个问题我们当时没有完全解决"，比编一个圆满结局可信得多。

## 若只问一句"三个里最印象深刻的是哪个"

优先讲项目二 CO₂ 问题——层次最好：占用驱动控制 → 节能 X% → 结果看起来很好 → CFD 发现 CO₂ 升高 → 分析控制逻辑 → 发现单一 occupancy 前馈局限 → 提出 occupancy + CO₂ 反馈 → 得出多目标控制认识。同时体现：HVAC 系统理解、数据分析、工程判断、批判性思考、诚实面对局限。
