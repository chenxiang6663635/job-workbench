## Q1 为什么研究传感器缺失？

**关键词**：真实环境 / 传感器故障 / 训练假设失效 / 部署退化 / 提前模拟

**主答（40s）**：因为训练时"数据完整"的假设在生产环境不成立。真实建筑里温度、湿度、风速这些传感器会故障、断线、丢数据，有些场景甚至配不齐全部变量。如果模型只在完整数据上训练，部署到不完整输入时性能就会退化。所以我在受控缺失场景下研究两件事：模型在缺失输入下还稳不稳（鲁棒性），以及它对哪些传感器依赖最深——为后续降低传感器依赖的部署方案提供依据。

**追问**：① 为什么不直接在真实系统里测？② 你模拟的缺失和真实传感器故障有什么区别？

---

## Q2 数据从哪里来，输入和标签是什么？

**关键词**：约 2.1 万样本 / 11 维输入 / 4 环境传感器（ta/tr/rh/vel）/ 三分类 / 类别不均

**主答（40s）**：数据集约 2.1 万条样本，热感觉三分类（偏冷 / 中性 / 偏热）。输入以 4 个环境传感器变量为主——空气温度、平均辐射温度、相对湿度、风速，它们也是我受控缺失的重点对象；全特征模型共 11 维，还包含服装、活动量、性别、年龄、季节等个体与场景变量。三个类别数量不均——中性最多（约 45%），这也是我选 macro-F1 的原因之一。数据集的正式来源论文和被试人数我还在核对。

**追问**：① 为什么只对 4 个环境变量做缺失，个体变量不做？② 类别分布具体是什么？为什么中性最多？

---

## Q3 为什么选择 XGBoost？

**关键词**：表格数据 / 非线性交互 / 训练效率 / 原生缺失处理 / 工程可解释

**主答（40s）**：XGBoost 适合结构化表格数据，能捕捉变量间的非线性关系与交互，训练效率高，方便在大量缺失场景和多组随机设置下反复比较。它还有基于默认方向的原生缺失处理机制，正好可以和其他插补方法做对比。我选它不是因为"准确率最高"，而是它在缺失场景实验、鲁棒性对比和工程可解释性上更合适。

**追问**：① 换 LightGBM 或神经网络会怎样？② XGBoost 的原生缺失处理机制是怎么工作的？

---

## Q4 A0、A1、A2、A3 分别在验证什么？

**关键词**：训练/测试完整性 / 基线 / 部署退化 / 缺失感知恢复 / safety check

**主答（45s）**：这四组区分训练集和测试集的完整性。A0 是完整训练、完整测试，作为理想基线；A1 是完整训练、缺失测试，模拟部署端突然缺数据，看退化多少；A2 是缺失训练、缺失测试，看"缺失感知训练"能不能把性能救回来；A3 是缺失训练、完整测试，只做安全开关——确认提前适应缺失不会把正常情况也搞坏。一句话：A1 看退化、A2 看恢复、A0 是基线、A3 是安全开关；A1→A2 只改训练侧，把"退化"和"能否补救"分开归因。

**追问**：① A3 为什么不承担主结论？② A2 和 A1 的缺失分布一致吗？

---

## Q5 missingness 是怎么构造的？

**关键词**：受控随机掩盖 / MCAR / 只抹 4 环境变量 / 10%–50% / 独立随机重复

**主答（45s）**：我采用受控随机掩盖构造传感数据缺失场景：按位置均匀随机抽样、不依赖任何特征或标签值，属 MCAR；每次只对 4 个环境传感器变量之一在部分样本上置空，缺失率 10%–50%，并在多组随机重复下评估。工程含义对应两类真实场景——"传感器通道暂时离线导致整批缺失"和"单变量部分样本丢包"；如果要模拟传感器持续漂移或系统性失效，那是 MAR/MNAR 机制，属后续扩展。

**追问**：① 你的 mask 只作用于环境变量，个体变量为什么不缺？② 不同缺失机制（MCAR/MAR/MNAR）对结论会有什么影响？

## Q6 为什么使用 macro-F1 而不是 accuracy？

**关键词**：三分类 / 类别不平衡 / 等权平均 / 多数类主导 / 辅助指标

**主答（35s）**：我的数据三个热感觉类别不均衡——中性类别占多数。如果只看整体 accuracy，样本多的类别会主导得分，少数类预测差也看不出来。macro-F1 先对每个类别单独算 F1，再等权平均，让每个类别对最终分数权重相同，能更均衡反映模型在不同类别上的识别能力。所以 macro-F1 是主指标，accuracy 作为辅助指标一起报告。

**追问**：① 三类里哪一类最难分？② 有没有看 Precision/Recall 和混淆矩阵？哪类更容易漏报？

---

## Q7 哪个变量缺失影响最大，为什么？

**关键词**：空气温度最敏感 / 单 seed pilot / 趋势非定论 / 信息贡献 / 替代性

**主答（40s）**：首轮单 seed 分析显示，4 个环境传感器里空气温度缺失影响最大，其次辐射温度、湿度、风速——温度类变量更敏感，说明它们对热感觉预测的信息贡献更高、更难被其他变量替代。但这只是首轮单次实验的趋势，还没跨多组随机设置冻结，所以我说的时候会加"初步趋势"限定，不叫最终结论。

**追问**：① 为什么温度类变量更敏感？② 这个排序跨不同缺失率会变吗？

---

## Q8 不同缺失处理策略有什么差异？

**关键词**：5 种 handler / 原生缺失处理 / 均值 / 中位数 / KNN / 迭代插补 / train-fit test-transform

**主答（45s）**：我对比了 5 种：XGBoost 原生缺失处理、均值插补、中位数插补、KNN 插补和迭代插补。所有方法都遵守防泄漏铁律——在训练集上 fit、测试集上 transform。比较重点是"退化—恢复"权衡：插补类整体更贴近完整数据基线，原生缺失处理在部分场景退化更明显；但没有一种在所有缺失场景都最优。

**追问**：① 插补类方法里哪个最好？为什么？② 你如何确保插补器没有看到测试集信息？

---

## Q9 "轻量化 / 降低传感依赖"做到什么程度？

**关键词**：Level B / 探索可行性 / 未做变量组合删减 / 未部署 / 后续路径

**主答（40s）**：目前是探索可行性（Level B）：已完成缺失鲁棒性实验和变量敏感性初步分析，研究可为后续传感器配置优化和降低输入依赖提供依据。但我没有做变量组合删减实验，也没有任何部署——所以我不说"已实现轻量化部署"，也不说"已评估减少部分传感输入后的性能变化"。后续路径是：结合缺失敏感性、解释和性能变化识别关键变量 → 少变量候选组合 → 少参数模型重训加复测。

**追问**：① SHAP 排名低就一定能删吗？为什么不行？② 少参数模型重训里"少参数"指什么？

## Q10 迁移到真实 HVAC 或数据中心，最大挑战是什么？

**关键词**：数据口径差异 / 真实缺失机制未知 / 控制闭环验证 / 对象迁移 / 不能直接套用

**主答（45s）**：最大的挑战是"对象和数据口径"不能直接迁移。我的研究在热舒适数据上验证，迁移到真实 HVAC 或数据中心需要三件事：一是重新定义任务——数据中心关心的是机柜热点风险和预警，不是热感觉；二是真实缺失机制可能不是 MCAR，需要先做数据质量诊断再决定缺失处理策略；三是必须做控制闭环验证——在真实系统里，模型输出要变成风机、阀门、冷机的动作，需要重新评估延迟、鲁棒性和降级控制。目前这只是方法论可迁移，不是已落地。

**追问**：① 数据中心最关键的缺失变量可能是什么？② 如果真实缺失是 MAR/MNAR，你的实验结论还成立吗？

## 压力题：这不就是 XGBoost 做分类吗，创新在哪里？

**关键词**：不是算法创新 / 问题设置 / 对照实验体系 / 缺失鲁棒性 / 工程依据

**主答（45s）**：XGBoost 本身不是这个课题的创新重点。这个项目的重点在于面向"传感器缺失"这一真实部署问题：一是构建了 A0 到 A3 的对照实验体系，把"完整数据上准确"和"缺失输入下是否可靠"明确区分开；二是系统比较了 5 种缺失处理策略，并分析缺失感知训练能否恢复性能；三是为模型进入 HVAC 控制前端时的数据可靠性、传感器依赖和部署约束提供实验依据。价值在问题设置、实验设计和鲁棒性分析，不在模型本身。
