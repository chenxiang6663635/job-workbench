# 求职证据实验室（WorkBuddy 参赛演示）

> 本目录是 **Job Workbench** 的一次**参赛演示归档**，不是 Job Workbench 本体。
> 完整产品是本地优先的职业行动工作台：岗位分析、简历版本、投递追踪、面试准备、Offer 对比。
> 这里只有其中一个环节的可交互切片。

## 这是什么

一个单文件网页：拿一段经历问「真的能写进简历吗」，按**证据三态**（有记录可核对 / 暂无资料依据 / 待补档案）给出不同处理，并展示为什么"AI 不能替你编造经历"。

由 WorkBuddy 完成创作与发布，用于 2026 年 10 月「1024 造物挑战」。

| 本演示（静态单页） | 完整桌面版才有 |

## 关于「由 WorkBuddy 创作」的说明

**把 HTML 提交到 GitHub，本身不能证明它由 WorkBuddy 创作** —— 这两件事不同：

| 证据类型 | 在哪里 |
|---|---|
| 作品产物（页面本身） | 本目录（入库） |
| 创作过程（会话记录、发布标记、应用注册表） | **本机，刻意不入库** |
| 参赛提交与审核记录 | 赛事平台侧 |

创作过程材料不入库是**有意为之**，不是遗漏：

1. 会话记录含完整过程原文与个人路径（`C:\Users\…`），仓库是公开的；
2. 发布标记（`.wbapp_*.genie`、`.workbuddy/applications.yaml`）留在本机才是"活证据"，强行入库反而降低其证明力；
3. 赛事抽查若需核对创作方式，另出示 WorkBuddy 侧记录（应用 ID 与发布记录可对上）。
