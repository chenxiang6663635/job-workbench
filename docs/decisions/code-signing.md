# 代码签名：暂不采购（等触发条件）

> 决策日期 2026-10-02 · 状态：生效中（随时可重审）· 来源：issue #202（三份独立审查 + PR #200 复核）

## 结论

**当前不采购代码签名证书**，维持「未签名 + SHA256SUMS + 安装说明 + 文档如实登记」的补偿组合；
下方触发条件满足时，按本文的推荐路径执行。

## 触发条件（任一满足即重审）

1. SmartScreen 误报成为高频 issue（出现真实用户报告，且非偶发）；
2. 下载量进入陌生人规模化使用（由维护者按版本下载数据判断一次）；
3. 分发渠道要求签名（如 winget 上架、应用商店收录）。

## 选项矩阵（2026-10-02 网络核实，采购前须向证书商复核——不是承诺）

| 选项 | 资格 | 价格参考 | SmartScreen 效果 | CI 自动化 |
|---|---|---|---|---|
| Azure Trusted Signing（旧名 Artifact Signing） | **不可用**：限美国 / 加拿大、需 ≥3 年可验证的组织实体（个人排除） | ~$10/月 | 信誉快速积累 | 好（托管签名） |
| OV 证书（国际 CA：Sectigo / Certum / DigiCert） | 以企业身份为主；个人申请可行性需逐家确认 | $215–400/年 | 按版本积累信誉（非立即） | pfx 进 Secrets + signtool，或云签服务 |
| OV 证书（国内 CA：沃通 / CFCA 等） | 个人可申请（需身份证明） | ¥1000–5000/年 | 同上（证书在微软信任列表内即被 Windows 验证） | 同上 |
| EV 证书 | 需实体身份 + 硬件令牌 / 云 HSM | $280–690/年 | **立即**获得信誉 | 硬件令牌不可入 CI；须云签服务（额外费用） |
| **不签名（现状）** | — | 0 | 首次运行提示 + 每版本信誉归零；补偿 = 安装说明 + SHA256SUMS + SECURITY.md 如实登记 | 无需改造 |

## 若触发：推荐执行路径

1. **首选国内 CA 的 OV（个人可申请档）**——资格门槛与成本最低；
2. 证书以 pfx 存 GitHub Secrets（受仓库保护 + 2FA），`release.yml` 构建后加签名步骤
   （electron-builder 原生支持 `win.certificateFile` + `CSC_KEY_PASSWORD`）；
3. 签名后复核 electron-updater 链路（签名包与 `latest.yml` 哈希的兼容）+ `signtool verify /pa`；
4. 真机下载核验（SmartScreen 行为变化必须真机确认，CI 测不了）。

## 为什么不"先买个最便宜的"

- 签名是**持续成本**（按年续费），收益与用户规模正相关；
- OV **不能立即消除** SmartScreen（仍需按版本积累），第一年的实际体验大概率不变；
- 现有补偿（安装说明 + 校验和 + 诚实登记）已覆盖「知情同意」层面——签名解决的是信任信号，
  在用户数少的阶段不改变实际风险；
- 提前采购还有**反向成本**：私钥托管面扩大（多一处可泄漏的密钥），需要配套的轮换与应急流程。
