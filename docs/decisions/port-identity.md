# 决策：端口身份——8765 的归属判据与冲突处理

- 状态：已采纳（2026-10-07）
- 相关：`web/electron/backend_process.js`（`checkHealth` / `isHealthy`）、`web/backend/main.py`（`/api/health` 与 `_is_our_service`）、`web/start.ps1`（端口释放）、`web/frontend/scripts/capture-screenshots.mjs`（`waitForHealth`）、`tests/test_port_identity.py`

## 背景

本地后端固定监听 `127.0.0.1:8765`（`backend_process.js` 顶部常量）。这个端口上会出现多种**合法的占用者**：安装版后端（`job-workbench-backend.exe`）、源码形态 `web/start.ps1` 拉起的 uvicorn、上一次没有退净的任一形态。围绕「谁在 8765 上」出过两类真实事故：

- **2026-09-25**：排障时对 8765 的占用进程无条件 `Stop-Process -Force`，误杀了用户正在运行的安装版后端——「清端口前先确认归属」自此成为操作纪律。
- **2026-10-04**：验证数据根迁移时迁移「没有发生」——原因是 8765 上还在跑**旧后端**，验证请求落到了旧进程上。把「已在跑即复用」当作省事，代价是**界面与数据根可能对不上**。

现状的三个事实（本 ADR 的适用范围）：

1. **身份判据是健康探测**：桌面端启动时 `checkHealth` 通过就「复用已在运行的后端」（不再 spawn）；`main.py` 独立启动时端口被占且 health 通过就「直接开界面」并退出 0；截图管线 `waitForHealth` 同款。
2. **但判据此前是子串匹配**（`body.includes("ok")` / `b"ok" in r.read()`）：任何返回体含 "ok" 字样的本地服务都会被当作「后端已在」——复用会接上一个陌生服务。
3. **开发脚本会强杀占用者**：`web/start.ps1` 对 8765 / 5173 上的任何监听进程直接 `Stop-Process -Force`（源码形态专用；桌面端与后端自身从不杀未知进程）。

## 决策

1. **身份判据收敛为「结构化健康响应」**：`GET /api/health` 返回 200 且 JSON 为 `{"status": "ok"}` 才算「本工作台的后端」。三处判定统一收紧（桌面端 `isHealthy` / 后端 `_is_our_service` / 截图管线），子串匹配退役（判据由 electron 自检与 `tests/test_port_identity.py` 钉住）。
2. **「已在跑即复用」语义保留，但只复用**通过身份判据的实例。这是本机自用场景的省事设计（dev 后端 + 桌面壳组合），不是跨实例共享数据：复用的后端用**它自己的数据根**——两者数据根不一致时以诊断为准（`jobws doctor` / 设置页「数据位置」卡），这是已知边界，不靠杀进程解决。
3. **自动杀进程只允许存在于开发脚本**（`start.ps1`，且保持「先打印 PID 再杀」）；桌面端与后端永不杀未知占用者。人工 / 代理清端口前先确认归属（2026-09-25 事故的纪律化）。
4. **端口固定，不引入换端口解决冲突**：更新链、导航守卫（`url_guard` 的 origin 严格比对）、通知与文档全部钉在 8765。就绪等待类探测（`start.ps1` 启动后轮询、Playwright `webServer.url`、`smoke_backend_exe.py`）**不算身份判定**——它们等的是自己拉起的进程，不适用第 1 条。
5. **不引入 token 级身份**：本机 loopback + 单用户；与「本地 API token」技术债一并复评（见下）。

## 已评估的替代方案

- **保持子串匹配不动**：最低成本，但「返回 ok 字样的陌生服务被复用」按定义是身份漏洞——收紧的代价只有三处各几行，收益是把「接口看着正常、连的不是我们的后端」这类最难排查的故障从结构上消掉。
- **启动时自动清端口（杀占用者）**：让启动「总是成功」，但与「绝不误杀用户进程」直接冲突，且把数据分裂问题藏得更深（杀掉的可能是另一个形态的后端）。否决。
- **给 health 加应用标识 / token 校验**：结构化字段已经能区分「本工作台」与「恰好会说 ok 的服务」；更强的身份留给有跨用户场景的批次（本地 API token）一并设计。暂缓。
- **换端口（8765 → 动态端口）**：牵动更新链、导航白名单、深链与文档，收益仅是回避冲突。否决。

## 复评条件

- 出现一次「身份判据误放行 / 误拒绝」的真实实例（陌生服务被复用，或本工作台实例被当成陌生）；
- 「本地 API token」进入实施（届时身份与鉴权一并设计）；
- 多实例 / 多用户托管形态出现。
