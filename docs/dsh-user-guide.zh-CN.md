## 一、产品定位与交付关系

Job Workbench 是**一个产品、一套领域实现、一条版本线**，通过多个第一等交付入口使用：

| 入口 | 适合什么 |
|---|---|
| 桌面端 / Web | 完整可视化业务操作（八个模块） |
| CLI | 命令与本地自动化 |
| MCP | AI 宿主的工具协议 |
| **DSH 插件** | **AI 原生工作台入口**（本指南） |

DSH 插件**不是独立项目**，也不要求界面与桌面端相同；它与桌面端共享同一份数据根、同一套业务语义、同一个版本号。区别只在**交互形态**：桌面端给你按钮，DSH 给你**对话 + 工具调用**（17 个 MCP 工具、9 个技能、可选 preset）。
**原生右栏（方案 D）目前仍是设计，不可用**——它卡在客户端 ↔ Node 的数据通道验收，准入判据见 [`ROADMAP.md`](../ROADMAP.md) 的候选池与 [spec §9.3](specs/2026-10-19-dsh-native-workbench.md)。

## 二、安装、初始化与升级

### 2.1 安装（✅ 隔离实测）

```powershell
# 方式一：一键安装脚本（推荐，幂等，可反复跑；先 -DryRun 只打印计划）
irm https://raw.githubusercontent.com/chenxiang6663635/job-workbench/main/integrations/dsh/scripts/install.ps1 | iex

# 方式二：官方 CLI
dsh plugin --profile <你的profile> add dsh-job-workbench
```

脚本做五件事：① 工作区放行（pnpm 的 `minimumReleaseAgeExclude`）② 装包并写入 `dependencies` 与 `dsh.profile.bundles` ③ 校验挂载 ④ 幂等移除旧手工挂载行（带备份）⑤ **初始化工作区**。

> CLI 位置提示：DSH 桌面版把 CLI 随 runtime 发布在
> `D:\tools\dsh\resources\runtime\cli\bin\dsh.cmd`，**不在 PATH 上**——`where dsh` 为空不代表没装。

### 2.2 首次使用：工作区必须先存在（✅ 隔离实测）

MCP 服务在**启动时**就要求 `<数据根>\personal` 已存在，否则直接退出、**17 个工具一个都不注册**。两种情形：

- **未设** `JOBWS_DATA_DIR`：首次启动会在默认数据根（`%APPDATA%\job-workbench\data`）**自动建**空骨架（14 个文件 / 6 个模块），并在 stderr 说明；
- **设了** `JOBWS_DATA_DIR` 但目录里没有 `personal`：仍然报错——那通常是路径写错，静默建成工作区比报错更难发现。此时手动跑一次：

```powershell
jobws-mcp --init      # 幂等，不覆盖已有文件
```

### 2.3 升级 / 卸载

- 升级：重跑安装脚本即可（幂等）。
- 卸载：`dsh plugin --profile <p> remove dsh-job-workbench`，**数据零影响**（工作区文件不受波及）。

## 三、核心功能与能力边界（八模块）

DSH 插件承载的是整个 Job Workbench，不只是"投递提醒"。下表说明每个模块**当前在 DSH 能做什么**（依据 `docs/four-ends.md` 能力矩阵，2026-10-19 机械核对：54 项能力中，16 项两端都有、34 项仅桌面端、1 项仅 MCP）：

| 模块 | 在 DSH 当前能做的 | 边界 |
|---|---|---|
| **总览** | 看板摘要、评分校准（`dashboard_summary` / `score_calibration`）✅ | 固定近 7 天视角 |
| **岗位决策** | 读岗位与 JD/解析卡、评分校验（`list_jobs` / `read_job_text` / `score_jd`）✅ | 新建/改名/删除岗位、抓取 JD 链接需桌面端 |
| **投递管理** | 列表、新增、更新、导入（`list_applications` / `preview_*` / `apply_approval`）✅ | 阶段时间线、删除需桌面端 |
| **简历工坊** | 技能给出改写与反编造建议 📋 | **PDF 渲染与归档不在 MCP 工具面内**，需桌面端或仓库 |
| **面试准备** | 题库查询、新增、导入 ✅ | 训练流程、答题记录、错题重练需桌面端 |
| **招聘进展** | 面试记录列表/新增/更新 ✅ | 邮件、联系人、宣讲会、Offer 的完整管理需桌面端 |
| **事实与素材** | 由技能引导读取事实卡 📋 | 暂无专用只读 MCP 工具 |
| **工作台设置** | `jobws.info` 连接与数据根诊断 ✅ | 凭据、备份还原、数据迁移、删除**只归用户本人操作** |

> 「装了 9 个技能」不等于「9 种工作流在 DSH 里都能跑完」——这是当前的真实边界，不是缺陷清单。

## 四、自然语言使用流程

在 DSH 会话里直接说人话即可，技能会按需触发：

| 你说 | 会发生什么 | 要注意 |
|---|---|---|
| 「看看我最近有哪些投递需要跟进」 | 调 `dashboard_summary` 返回近期待办 | 目前是固定近 7 天视角 |
| 「帮我看看这家公司的 JD 值不值得投」 | 走 `jwb-jd`：读 JD → 资格门槛 → 评分 → 差距 | 找不到 JD 原文时会明说，**不编造** |
| 「把 A001 更新到一面」 | `preview_update_application` 给出差异 → 你确认 → `apply_approval` 落盘 | **预览不等于保存** |
| 「分析我各评分档位的实际转化」 | 调 `score_calibration` | 样本不足时会标注 `too_few_samples`，不强行给结论 |
| 「帮我生成这家公司的投递版 PDF」 | 引导你到桌面端/仓库 | **不会**声称已生成，**不会**编造保存路径 |

**四条使用规则**

1. 数据看起来不对时，先问「我的工作区和数据根是什么」——让模型调 `jobws.info` 看诊断，不要自己翻文件。
2. 查询和分析优先用只读工具。
3. 写入必须确认：先看差异，同意才落盘。
4. 不编造、不代投：缺 JD、缺事实、缺阶段证据时会明确告知；本插件**不会**代替你向招聘网站投递。

## 五、数据与安全规则

> 隐私承诺的权威底稿是 [`docs/data-flow-matrix.md`](data-flow-matrix.md)；本节是它的 DSH 摘录，冲突时以底稿为准。

- **Local-first**：所有数据在你本机工作区（纯文本 CSV / Markdown）；MCP 服务自身不联网，只读写本地工作区，**不会自动同步到项目方服务器**。
- **DSH 面板取数不经模型**（📋 方案 D）：右栏的状态、摘要、待办由 Node 侧直连本地 MCP 实例取得，全程不出本机——打开面板、切换模块、刷新状态**不产生**任何出网。
- **AI 对话可能出网**：当你**主动**向 AI 提问时，宿主可能把工具返回的内容连同你的问题发给**你配置的模型服务商**。这一层由你选择的宿主与模型决定，不在本应用控制范围内。需要处理简历、事实库、邮件等敏感内容时，请自行判断当前模型是否合适。
- **同一数据根**：DSH 与桌面端读写同一份数据；切换工作区是显式动作，不存在"静默回退到另一份旧数据"。
- **两段式写入**：`preview_*` 只给令牌与差异，`apply_approval` 才落盘；这是协议上的留痕，不靠提示词约束。
- **反编造**：生成简历建议前会读事实卡；没有证据支撑的内容会被标出来，而不是补写。
- **敏感信息**：`personal/` 下的 IMAP 与服务商密钥只在你本机；不要贴进外部服务或提交信息。

## 七、能力限制与故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 装好了但会话里一个工具都没有 | `<数据根>\personal` 不存在，MCP 服务启动即退出 | 跑一次 `jobws-mcp --init`；或让它用默认根自动初始化 |
| 显示"服务离线/功能已支持但连接不可用" | MCP 服务没起来或断了 | 看 `jobws.info` 诊断；确认数据根是否可读 |
| 找不到某个技能 | 技能来源应是**插件包**，不是仓库 `.agents/skills` | 检查 `dsh.profile.bundles` 是否含 `dsh-job-workbench` |
| 让生成 PDF 却被引导去桌面端 | PDF 渲染**不在** MCP 工具面内 | 用桌面端，或在仓库里跑 `jobws resume render` |
| 读岗位正文失败 | DSH **不桥接 MCP 资源**（`jobws://`） | 让模型用 `read_job_text` 工具读，不要用资源读法 |
| 阶段时间线看不到 | MCP 不提供阶段时间线 | 用桌面端的投递详情 |

## 八、版本与支持范围

- DSH 插件与 Job Workbench **同号发布**（如 `26.10.0`），宿主兼容要求见 `integrations/dsh/package.json` 的 `engines.dsh`。
- 当前平台：**Windows（win32-x64）**；其他平台子包尚未提供。
- `v26.11.0` 首发时，DSH 提供的是**现有 MCP 能力**（17 工具 / 9 技能）；方案 D 的原生界面在其后的版本中逐步实现。
