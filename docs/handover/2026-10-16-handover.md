## 七、踩过的坑（照着避）

1. **CHANGELOG 文本绝不能作为 shell 参数传**——PowerShell 把反引号当转义符，会污染 + 截断条目。**必须把文本写进 .py 脚本再执行**。
2. `CHANGELOG.md` 是**混合行尾**（644 LF + 10 CRLF 基线）：按 LF 切分、`\r` 留在行尾随行搬运；新行纯 LF；插完复核 LF/CRLF/CR 三个计数。
3. **`lint legacy-imports` 只在 CI 跑**（本地 pre-commit 链不含）：旧名 `tracker`/`approval`/… import 点**只许减不许增**；新测试要用 `from jobws_core import ...`。
4. `git grep` **只搜已跟踪文件**——查新文件（未 `git add`）要用 `Select-String`。
5. Windows 建链：目录链用 `os.symlink` 失败后回退 `cmd /c mklink /J`（不要特权）；**文件级链要特权，本机只能 skip**，CI 的 ubuntu 才真跑——凡是文件链用例，本机绿不代表验过。
6. e2e 跑的是 `web/frontend/dist`（**gitignored**）：改了 `src/` 必须**先 `npm run build`** 再跑 e2e，否则「源码已修、产物未更新」会给出假红/假绿。
7. CodeQL：**分析 job 成功 ≠ 无告警**；新告警会在 PR 上开 review thread，配合「会话必须解决」直接**阻塞合并**（本轮 14 条 `py/path-injection`，逐条回复理由后 resolve 才放行；告警本体留给基线批次）。
8. 前端命令含 `vite` / `build` 会被本机包装器判成 watch 并吞输出；PowerShell 多行命令里带 `cmd /c` + 括号会被 cmd 接管而报错（拆分即可）。
9. 子代理可能**网络中断留下残局**（本轮 S2：未提交、未写报告、22 个文件散在工作区）——接手时先 `git status` + `git log main..HEAD` 摸底，逐项复核后再提交。
10. 数据根迁移的**反向搬迁当前不支持**（#304）：`root_id` 随数据搬走，`_already_current` 会把「迁回旧位置」误判为「已是当前数据」。
