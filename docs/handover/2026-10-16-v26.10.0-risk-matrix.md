## 三、触发条件与暴露面（hotfix 裁决的依据）

1. **P2**：需「应用根与数据根**同名工作区**」+ 带 `ws` 的请求。
   - NSIS 安装形态（Program Files，只读）：**推断**写路径会响亮失败（OS 只读 → 原子写抛错 → 500）而非静默污染——**未实测**，隔离环境安装后验证列为 G2 动作；读路径可能返回安装目录里的旧副本（若用户曾在安装目录留下同名工作区）。
   - 便携 / 源码形态（应用根可写）：读旧数据 + **写落旧副本**（真实污染）。
   - 默认安装流程不在应用根建工作区（新建落数据根）→ 触发需**非默认布局**；至今无实际报告。
2. **#313**：需「用户在设置页记住过数据根 B」+「A/B 都有 `personal`」+ 用 CLI 且不带 `--workspace`。写暴露同样只在应用根可写时成立（源码/便携）。
3. **P1-B**：需用户主动走 data-root 迁移的「搬回旧位置」路径，并看到误导性「已是当前数据」文案（#305 已改为如实说明"反向迁移当前不可行"）。
4. **S2**：需工作区内已有指向外部的 symlink/junction（用户不可感知的材料）+ 读取经模型代传路径参数。可利用性维持此前"低"的判定，且 **v26.10.0 并未缺失核心防护**。

## 四、可立即给用户的规避措施

- 核对两处是否存在同名工作区：安装目录（或仓库根）与数据根（设置页「数据位置」会显示当前根与来源）；
- CLI 显式传 `--workspace <数据根>/personal`，或设 `JOBWS_DATA_DIR=<数据根>`；
- 不执行「搬回旧位置」的迁移，等 26.11.0。

## 五、裁决：**不做 `26.10.1`，全部纳入 26.11.0**（附升级条件）

**理由**：四条风险的共同触发前提都是**非默认布局**（双根同名 / 记住过数据根 / 主动
迁移 / 已有外部链接），无已知实际事故；NSIS 安装形态（绝大多数用户）下写路径因只读
而失败，不构成静默数据分叉；hotfix 需要一条完整第二发布链（从 tag 挑 5+ 修复、重建、
重签、重发），代价与风险高于收益；`main` 已含全部修复，发布链会做真机 + 回滚验证。

**升级为 hotfix 的条件（任一命中即重启评估）**：
- 出现任何真实报告（数据"消失" / 被覆盖 / 两端不一致）；
- 隔离环境实测证明 NSIS 安装形态下也存在**静默**错根写（而非 500）；
- 用户要求提前修。

**留待发布链（G2/G3，须用户在场）**：隔离环境安装 v26.10.0，对 P2 错根写与 S2 越界
各做一次定向探针，用临时目录、不碰真实数据；结果回填本节。
