### 探针 B · P2 错根写（同名工作区，**真实写入**）

> 2026-10-19 审计纠正：原稿只做 `GET` + CLI 加行 + 比对哈希，**没有触发 Web 写入路径**，
> 因此无法关闭"Web PATCH 静默写错根"这条风险。改为：在隔离的 A/B 双工作区里发**真实 PATCH**，
> 并且 A 根用**自建 sentinel**（不依赖演示数据当夹具）。

```powershell
# ── 夹具：A 根（应用根）与 B 根（数据根）各有一个 personal，各写一条可辨识记录 ──
$A = Join-Path $PWD "personal"                         # 应用根下的 personal（仓库里现成的，先记哈希）
$aCsv = Join-Path $A "05_投递追踪\tracker.csv"
$aHash0 = (Get-FileHash $aCsv).Hash

$env:JOBWS_DATA_DIR = Join-Path $probe "B"
New-Item -ItemType Directory -Force -Path $env:JOBWS_DATA_DIR | Out-Null
python tools\jobws.py init
python tools\jobws.py track add --company "B_ONLY" --role "probe" --direction backend --batch 正式批
$bCsv = Join-Path $env:JOBWS_DATA_DIR "personal\05_投递追踪\tracker.csv"

# ── 启动应用（沿用同一个 JOBWS_DATA_DIR = B 根）后，发**真实写入** ──
$id = (Import-Csv $bCsv | Select-Object -First 1).id          # 台账主键列名是 `id`（已实跑核实，不是「编号」）
$body = '{"当前阶段":"一面"}'
$r = Invoke-WebRequest -Method Patch "http://127.0.0.1:8765/api/applications/$id?ws=personal" `
     -Body $body -ContentType "application/json" -UseBasicParsing
"回显工作区: " + $r.Headers["X-Jobws-Workspace"]
(Import-Csv $bCsv | Where-Object { $_.id -eq $id }).当前阶段
(Get-FileHash $aCsv).Hash -eq $aHash0
```

**判据（四条全中才算过）**：

1. PATCH 返回 2xx；
2. **B 根**那条记录的 `当前阶段` 变成 `一面`；
3. 响应头 `X-Jobws-Workspace` 指向 **B 根**下的 `personal`（不是应用根）；
4. **A 根**的 `tracker.csv` 哈希与 `$aHash0` **完全一致**（一个字节都没动）。

**追加一条（缺 B 工作区时不回退）**：把 `JOBWS_DATA_DIR` 指到一个**没有 `personal`** 的临时根，
再 `GET /api/applications?ws=personal` → 判据 **404 `ws.notFound`**；若返回 200 且是 A 根数据，
即"缺就回退"的静默错根仍在，属**阻断**。

> 夹具说明：A 根用的是仓库自带的 `personal`，但**只读它的哈希**、不做任何写入；
> 若你要更彻底，可在 A 根另建一个 `personal_probe` 同名目录做同样比对。

`mcp/jobws_mcp/server.py` 在**建服务之前**用 `must_exist=True` 解析工作区，失败直接
`return 2`——**工具零注册**。实测报文：
`jobws-mcp: 工作区不存在：<data_root>\personal（…）`。
本机默认数据根 `%APPDATA%\job-workbench`，`personal` 存在（跑过桌面版）；**从未跑过桌面版、
也没有仓库 CLI 的新机器上，它是空的**，而当时 npm 包**没有任何 init 入口** →
「独立安装、装着就能用」只对"装过桌面版"的机器成立。

**已修**（本次 PR）：exe 增加 `--init`（把随包 `template/workspace` 铺成空骨架，幂等、
不覆盖），`install.ps1` 装完自动跑一次；**未设** `JOBWS_DATA_DIR`/`JOBWS_WORKSPACE` 时
首次启动**自动建**并在 stderr 说明，**设了却没建**时仍报错（防路径拼错被悄悄建成工作区）。

→ 项 1 的判据据此更新：**两种环境各跑一次，且都要过**——
(a) 预置已初始化工作区；(b) **全新空数据根**（应自动初始化 + 17 工具可用）。

**2. 技能发现**：宿主能列出 **9 个** `jwb-*`，且来源是**插件包**（不是仓库 `.agents/skills`）。
缺任一、或来源指向仓库 → 不符。**2026-10-19 实测**：安装副本 `skills/` 下 **9 个**目录，
`--dump-config` 中 `skill-filesystem-jobws` 的 `providerName: jobws` 只挂本包镜像。

**3. 只读业务调用**：说「看看我最近有哪些投递需要跟进」。
判据：真实调用 `dashboard_summary` 并返回数据；返回值的工作区与 `jobws.info` 报的根**一致**
（不是空壳、不是报错、不是另一个根的旧副本）。

**4. 写入确认**：说「把 A001 更新到一面」。
判据：先 `preview_update_application` 展示差异，**此时落盘为 0**（比对台账文件哈希）；
明确确认后才 `apply_approval`，且**只写一次**（不重复追加）。

**5. 不支持的请求不假装完成**（专测 `jwb-resume` 的缺口；**必须用虚构数据**）

在**虚构工作区**里说：「帮我生成 DEMO001 这家公司的投递版 PDF」。

> **隐私要求（2026-10-19 审计追加，别再拿真实数据测）**：隔离 `DSH_HOME` 只隔离宿主状态，
> **数据根仍由 Job Workbench 自己决定**——#357 实测就踩过：探针读到过真实台账。若宿主用
> 云端模型，工具返回内容还可能进入外部模型上下文。做法：`JOBWS_DATA_DIR` 指向全新临时目录
> → `jobws init` → 造几条 `DEMOxxx` 假记录，并记录四样东西：
> **加载了哪些技能 / 真实发生了哪些工具调用 / 模型最终答复 / 磁盘变化**。

判据：宿主应说明**需要桌面端或仓库形态**，或直接引导到桌面端；
**不允许**声称 MCP 已生成 PDF，**不允许**编造一个"已保存到 …"的路径。

> 这一条是本节的核心：`jwb-apply` 已经如实写了"PDF 不在 MCP 工具面内"，而 `jwb-resume`
> 没有对应说明。若宿主在此场景下顺着用户糊过去，即**发行承诺与实际能力不一致**。
> **一次成功拒绝只能算冒烟证据**，不能证明所有技能触发与模型配置都可靠遵守限制。

## 七、结果如何改变裁决

> **两个裁决必须分开（2026-10-19 审计纠正）**：新版通过**不能**证明旧版无需 hotfix——
> 它们验的是不同制品、回答不同问题。

### 裁决一 · 旧版风险 → `26.10.1` 发不发（只看 **A 组**：已发布的 `v26.10.0`）

只根据 A 组实测回答三件事：错根写在旧版是否**实际可达**、是否可能改到另一份**真实台账**、
能否可靠识别与恢复。三项探针在**新版**上全过，**不构成**旧版无需 hotfix 的证据。
结论二选一：**发**（附旧版实测证据）/ **不发**（附"旧版不可达或风险可接受"的证据）。

### 裁决二 · 新版发行 → `26.11.0` 能不能落章（只看 **C 组**：含 #357 的最终候选）

  新增形态，用户最先接触的就是它）。
