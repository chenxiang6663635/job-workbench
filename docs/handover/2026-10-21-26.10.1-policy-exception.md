# 一次性发行政策例外：26.10.1 最小安全 Hotfix（2026-10-21 批准）

> **性质**：正式治理记录。批准一次性偏离 `docs/contributing.zh-CN.md` 的 fix-forward 规则
> （「不设 hotfix 分支」），用于 PYSEC-2026-4320（certifi / `emSign ECC Root CA - G3`）安全事件。
> 例外随 `26.10.1` 发布完成即失效，不构成长期分支策略变更。

## 一、为什么不能用常规 fix-forward

`docs/contributing.zh-CN.md` 规定 Hotfix 从 main 前进。但本次安全事件下该规则产出**非最小补丁**：

| 事实 | 数值（`git diff v26.10.0..main`，2026-10-21 实测） |
|---|---|
| 提交数 | 89 |
| 变更文件 | 292 |
| 其中产品代码文件 | 152（web/frontend 45、jobws-core 32、mcp 26、backend 24、tools 17 等） |
| 含未完成 G2/G3 验收的功能 | `#357 自动初始化`、`#323 筛选校准`、`#324 17 工具扩展` |

把 main 命名为 `26.10.1` 会让已发布用户收到一次**功能升级**而非安全补丁。因此批准一次性例外。

## 二、例外范围（唯一、限定）

| 项 | 规则 |
|---|---|
| 补丁基线 | `v26.10.0` 发布提交（`0f9cfd8`） |
| 分支 | `fix/26.10.1-certifi-hotfix`（一次性；用完即删） |
| 允许改动 | 只允许**两项已登记安全依赖修复**（certifi 与 pypdf，见 §三之二）落在两份依赖文件上，加必要版本元数据（`web/electron/package.json`、`.codebuddy-plugin/plugin.json`、9 个技能 metadata、`CHANGELOG.md`） |
| 禁止 | 任何 `v26.10.0` 之后的功能；任何 `integrations/dsh` 插件体系改动（`v26.10.0` 已有 `README.md` / `preset.yml` / `profile.patch.yml` 三份早期集成资产，但**尚无完整的 npm 主包 + Windows 平台子包 + 预构建运行时**分发形态） |
| 合并回 main | **禁止**（会把代码回退 89 个提交）；只允许**发布记录文档**进 main |
| 产物定义 | `v26.10.1` tag + GitHub Release（Release 工作流构建） |
| 发布授权 | 技术验收 + dry-run 通过后**再次单独批准** |

## 三、旧版受影响的实证依据

官方 `v26.10.0` 安装包（`job-workbench-setup-26.10.0-win64.exe`）离线取证：

| 步骤 | 结果 |
|---|---|
| 下载与核验 | 137,908,696 B；SHA256 `197fe10593eb50b127c87aaa690ad575aee7dc38b001110de5421e4df52ca954`（= 官方记录） |
| 解包 | 7-Zip 离线解包，**未执行安装程序、未启动其中可执行文件** |
| 随包 CA 清单 | `resources\backend\_internal\certifi\cacert.pem` = `9CC2A774…`（certifi 2026.7.22），**121 证书，含 `emSign ECC Root CA - G3`** |
| TLS 路径 | `tls_policy.py`：系统证书库优先；仅当 `ssl.create_default_context()` **创建失败**时回退随包 certifi。**是否触发取决于具体系统证书环境（本机实测无 emSign；其他环境未知），目前没有部署频度证据** |
| 系统根库（单机实测） | `certutil -store Root` 中 emSign / eMudhra 0 条 |

**结论**：旧版随包清单**实证**含受影响根；受影响路径条件性可达；无已知利用证据。
理由充分性（CVSS 9.1、修复成本低、已发布用户无法自动获得保护）支撑发布最小 Hotfix。

### 三之二：pypdf 依赖安全修复（2026-10-21 追加登记）

新披露 5 个 CVE，`main` / `v26.10.0` / 本分支**三处都锁 `pypdf==6.19.0`**：

| CVE | 修复下界 | 性质 |
|---|---|---|
| 2026-113786 | 6.21.1 | 未验证的 JPEG 数据加载 |
| 2026-113792 | 6.20.1 | outline 结构致无限循环 |
| 2026-113793 | 6.20.1 | PDF 解析资源消耗 |
| 2026-113794 | 6.20.0 | 不完整 xref 表致无限循环 |
| 2026-113795 | 6.20.0 | 多 filter 流过量内存 |

- 目标版本 **6.21.2**（覆盖全部下界；wheel `1d44d1a3a200f25062adff0085b02040e4646431ac2ccac22e42679e91466084`、
  sdist `0a3e1c5c886a1be03646c16a04827cc166c2a0575c971b26a4bf89686551c2d4`）；
- 风险边界：CVSS 4.0 **均为可用性影响**（`VA:L`/`VA:H`），机密性/完整性为 `N`；实际调用面 =
  `resume_import.py`（读用户导入的 PDF）与 `resume_build.py`（文本提取/A4/ATS）；**未证明五个 CVE
  在本项目全部可达**（部分依赖可选组件或特定解析路径），无已发生攻击证据；
- 依据 = 公开依赖风险 + 实际 PDF 输入面 + 现行 `pip-audit` 必需检查失败（P0 发行阻断）；
- **不放宽门禁**：不关闭 `pip-audit`、不添加 CVE ignore、不把安全扫描标为非必需。

> 两项修复（certifi + pypdf）一次性进入 `26.10.1`，**不另发 `26.10.2`**——用户已装旧版，一次更新
> 带走两项修复优于连续两次发补丁。未来若再现其他依赖告警，**仍须独立审查**，不得自动纳入本例外。

## 四、官网同步：拆成「发布前就绪」与「Release 公开后立即切换」两阶段

`site/scripts/build_site.py` 原只读 `web/electron/package.json`，下载页按 `v{{VERSION}}` 渲染；
站点仅在 main push 后发布。Hotfix 分支不改 main 版本字段 → 不处理则官网主按钮继续指向受影响的
`v26.10.0`。**但「tag 前就要求官网已指向 `v26.10.1`」是循环依赖**——Release 未公开时该资产 URL
不存在，提前切换会让用户下载 404。故拆成两阶段：

### 阶段 A：发布前硬门禁（tag 前必须全部满足）

1. 「已发布版本」机制已进主线并生效（`site/published-release.json` + 生产 fail-closed，#372 已落地）；
2. 站点当前展示**真实存在的正式版本**（现为 `v26.10.0`），中英文下载页与直链可用；
3. Hotfix 候选资产（安装包 / blockmap / `latest.yml` / SBOM / 校验和）已审核，升级与数据保留实测通过；
4. 切换与回退方案就绪：发布后更新元数据 → 触发 `site-dist` → 点击核验；失败可**回退元数据**到上一版并重发站点；
5. （可选，缩短窗口）切换期可把主下载入口临时指向 GitHub 稳定的 `releases/latest` 页面——它随正式
   Release 自动切换，不依赖文件名提前确定。

### 阶段 B：Release 公开后立即验收（发布流程的一部分，不是 tag 前条件）

1. 确认 GitHub Release 的 `v26.10.1` 资产真实存在，核对安装包 SHA256；
2. 将 `published-release.json` 更新为 `26.10.1` 并填入**真实** SHA256（不得用格式合法的占位值）；
3. 触发 `site-dist`，点击核验中英文下载页与直链；
4. 失败时回退元数据到上一版并重发站点（站点与 Release 解耦，回退不影响已发布资产）。

验收细则见 `docs/release-checklist.md` 的 Hotfix 段。

## 五、必验项（发布前）

| 风险 | 验收要求 |
|---|---|
| 版本元数据 | Electron / plugin.json / 9 技能 metadata / CHANGELOG 全部 26.10.1；NSIS 文件名与 `latest.yml` 版本一致 |
| 自动更新链 | 已装 26.10.0 能识别并升级到 26.10.1（**实测**）；`26.10.1 → 26.11.0` 目前只做**静态**版本比较与更新兼容合同核验——真实跨版升级必须等十一月 `26.11.0` 发布后再验证，现在不得宣称已通过 |
| 历史版本功能与数据 | 补丁不执行新功能的数据迁移、不覆盖既有工作区 |
| 内部 B 组隔离 | B 组（版本号仍 26.10.0、代码来自 `fc2ad96`）必须与公开更新链隔离，防被误"降级"到 26.10.1 |
