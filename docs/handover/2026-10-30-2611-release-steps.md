## 一、为什么必须等 11-01

`tools/release_assist.py` 的算法：

```python
ym = (today.year % 100, today.month)     # 11 月 → (26, 11)
used = [patch for tags in 当月]           # 11 月没有任何 tag
number = max(used) + 1 if used else 0     # → 0
```

实测：

```
10-30  jobws release version  →  26.10.2
11-01  jobws release version  →  26.11.0    ← 换月重新从 .0 起
```

## 三、动态验收：数据根（30 分钟）

两个场景**判据不同**，不能合成一条。

### 场景 1：默认模式（不复用）

**目的**：验证「默认不附着到别人的实例」。

```powershell
# A：占住 8765，指向数据根 X
$env:JOBWS_DATA_DIR = "<根 X>"
python -m uvicorn main:app --host 127.0.0.1 --port 8765   # 在 web/backend 下

# B：另开一个终端，不设 JOBWS_ALLOW_REUSE
python tools/jobws.py --workspace personal dashboard
```

**判据**：

| 观察点 | 期望 |
|---|---|
| B 是否附着到 A | **否**——拒绝并退出 |
| 退出码 | **2**（不是 0） |
| 提示文案 | 说清「端口被**另一个实例**占用」，并给出 `JOBWS_ALLOW_REUSE=1` 的出路 |
| A 是否被杀 | **否**——这是最容易错的地方（历史事故） |

### 场景 2：显式复用（`JOBWS_ALLOW_REUSE=1`）

**目的**：验证「用户显式选择复用时，用的是**被复用实例**的数据根」。

```powershell
# A 同上（数据根 X）
$env:JOBWS_ALLOW_REUSE = "1"
$env:JOBWS_DATA_DIR = "<根 Y>"     # 故意指向另一个根
python tools/jobws.py --workspace personal dashboard
```

**判据**：

| 观察点 | 期望 |
|---|---|
| 实际读的数据根 | **X（A 的），不是 Y** |
| 诊断输出 | 说清「附着到哪个实例、哪个根」 |
| 是否警告根不一致 | **是**——因为 `JOBWS_DATA_DIR` 只影响新进程，改不了已在跑的 |

### 为什么这两个场景必须分开验

`JOBWS_ALLOW_REUSE=1` 时「用被复用的根」是 **ADR 的既定语义**（否则复用没意义）。
把「数据根不一致必须拒绝」当成统一判据，会与复用功能自相矛盾——

> 这条冲突在 `2026-10-28-p0-closure.md` §一 与 §八 之间出现过一次，已按模式拆开。
