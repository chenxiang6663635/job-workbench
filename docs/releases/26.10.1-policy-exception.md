## 二、本次例外

原发行政策 §五要求发布前验证从 26.10.0 到 26.10.1 的完整自动升级。本次仅允许将客户端自动下载、`quitAndInstall`、自动安装及重启的端到端验证调整为公开发行后立即执行。

这项调整不代表上述能力已通过验证，也不允许在发行说明中宣称完整自动升级已通过。

## 三、发行前必须满足的条件

D′-1 保持已确认的无 FAIL、无 fatal 结论；正式 Tag 构建必须通过构建及 E2E 门禁；Draft Release 必须完成正式资产的哈希、版本、SBOM、`latest.yml`、安全 PEM 及真实安装验收。

正式安装包与此前 RC 如有字节差异，以正式资产重新计算的校验值为准。

## 四、明确接受的残余风险

维护者知悉并接受：旧版客户端虽然能发现更新，但真实下载、安装目录保持、自动退出、UAC、重新启动及中断恢复仍存在未经完整端到端验证的风险。

官方旧版设置为 `autoDownload=false`，下载与安装依赖用户确认。发布时保留官方手动下载安装路径与校验和，作为自动升级异常时的替代方案。

不得因此豁免数据损坏、安全资源不正确、安装失败或正式资产完整性问题。

## 五、发布后处置

Release 公开后立即验证公开更新元数据、客户端下载安装、重启和数据保持，并完成官网已发布版本切换。

如发现自动升级故障，记录失败路径并提供经过验证的手动安装指引；如发现可能导致数据损坏或严重安装问题的缺陷，立即停止相关推广、公告风险，并根据影响决定发布更高版本的修复。

不得重新将包含已修复安全风险的 26.10.0 推荐为主下载版本。

## A-2 撤回「P-2~P-5 必须在维护者日常电脑执行」

上一版草案把它写成硬性要求，**越界了**。正确表述：

| 验证项 | 可选路径（按实际能力选一） |
|---|---|
| 公开后元数据一致性（`latest.yml` vs Release 资产） | **任何环境均可**，纯文件比对 |
| 真实客户端能发现 / 下载 | ① 维护者自愿在真实 Win11 上做；② 在一次性 runner 上对**公开 Release** 再跑一次同类检查（可验元数据，不可验真实 Win11 GUI） |
| 真实客户端能安装 / 重启 / 数据保留 | 同上；若无法执行，**登记为未覆盖**并写入发行说明 |
| 官网 `published-release.json` 切换 | 任何环境，HTTP 比对 |

**若维护者不便在任何真实 Windows 上执行，可全部登记为未覆盖**——但发行说明不得宣称自动升级已实测通过。

## A-3 D′-1 已经覆盖的一条，与仍未覆盖的一条（更新更精确的风险描述）

> **更正（2026-10-26，维护者审计指出）**：
> ① 我此前说「正式包安装核查未执行」**是错的**——`release.yml:352-393`
> 「安装与卸载冒烟（NSIS /S）」在 package job 中**用本次构建的正式包**执行了
> `/S` 安装 → 探卸载器 → `/S` 卸载 → 等目录消失，且通过。
> ② 我此前说「只差 14 字节所以功能等价」**不成立**——14 B 是两个压缩包的
> **总长度差**，不是逐字节比较得出的差异；不能据此推断内容等价。
> 真正降低风险的是：同一 `ce789f4` 源码基线 + 锁定依赖 + 正式包安装冒烟 +
> RC 的深入升级验证。

我在上一版草案 §五 R-2 写「自动安装可能装错目录」——**D′-1 实际已经覆盖了它**：

```
upgrade-smoke.ps1:287   Invoke-Installer $OldExe @("/D=$testDir")      # 旧版装到自定义路径
upgrade-smoke.ps1:380   Step 'Upgrade to 26.10.1 (/S，不带 /D=)'        # 升级时**不指定目录**
收据 install_dir = D:\a\_temp\jw-smoke\Job Workbench                    # 仍回到原自定义路径
```

**⇒ NSIS 静默升级会沿用注册表里记录的旧 InstallLocation，不会产生第二份安装。** 这消除了 updater.js L82–84 注释里担心的场景。

**真正仍未覆盖的只有一条**，比「整个自动安装路径」窄得多：

| 未覆盖 | 为什么 D′-1 覆盖不到 |
|---|---|
| **`--updated` 模式** | `quitAndInstall` 传给 NSIS 的是 `["--updated","/S","--force-run"]`，而 D′-1 只跑过 `/S`（不带 `--updated`）。`--updated` 会让 NSIS 走「更新分支」（跳过部分检查、对运行中应用的处理不同），这条分支未被任何测试执行过 |
| **强制退出时机** | `quitAndInstall` 会**强制退出**应用；D′-1 是用户主动关闭后才安装。前者假设「未保存工作已落盘」，该假设未验证 |
| **`elevate.exe` 提权** | `isAdminRightsRequired` 或 `spawnLog` 遇 `EACCES`/`UNKNOWN` 时走提权；D′-1 静默安装从未触发 |

**这三条应作为 §四「残余风险」的具体化描述**，而不是笼统的「自动安装路径未验证」。

## A-4 `stopBackend()` 的补充事实

`updater.js:81` 的 `stopBackend()` 在 Windows 上使用**同步** `taskkill /f /t`，因此「调用处没有 `await`」**不等于**后端未被停止。但 `taskkill` 失败后的后续处理、以及 `quitAndInstall` 在应用仍在运行时的行为，仍未被 D′-1 覆盖。
