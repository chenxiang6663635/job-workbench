# v26.10.1 发布后残余风险处置决定（Post-Release Risk Acceptance）

> **性质**：对 [`26.10.1-policy-exception.md`](./26.10.1-policy-exception.md) 正文 **§五**
> 「Release 公开后立即验证客户端下载安装、重启、数据保持」**一次性的补充处置**。
> **不是**测试通过记录，**不是**对已完成事实的追认，**不追溯宣称已经履约**。
> **状态**：待维护者签字确认。

---

## 一、背景与决策

`v26.10.1` 已于 **2026-10-26 09:06:27 UTC** 公开发行。
政策例外正文 §五 要求公开后立即验证 P-2~P-5；附注 A-2 虽记载「可登记为未覆盖」，
但该附注**明示不构成正文**，不能自动免除 §五 的义务。

**维护者裁决：选择方案 2 —— 不再为 26.10.1 新建 P-2~P-5 自动化测试平台，
以本文件正式接受该残余风险。**

理由（四项既有证据）：

1. **S1** 已用真实官方 26.10.0 客户端在受控 HTTPS 环境验证更新发现，`S1_PASS 14/14`
   （含未信任 CA 时的拒绝负例）；
2. **P-1** 已验证真实公开 GitHub Release 的更新元数据、版本与资产可达性；
3. **D′-1** 已在同源码基线的 RC 上验证覆盖升级、数据保持与快照恢复（51 项 50/0/1），
   正式包另通过**真实安装/卸载冒烟**与**安全 PEM 逐字节核验**；
4. 自动更新**需用户两次主动确认**（`autoDownload=false`），且已提供**经过验证的正式安装包**
   作为手动更新途径。

**上述证据足以支持有条件接受剩余风险，但不足以宣称公开环境中的自动下载、安装与重启已经成功。**

## 二、六条硬性条款

### 1. 技术事实不得改写

P-2~P-5 维持 **`NOT_EXECUTED`**。

| 项 | 状态 |
|---|---|
| P-2 真实客户端能发现 | `NOT_EXECUTED` |
| P-3 真实客户端能下载 | `NOT_EXECUTED` |
| P-4 真实客户端能安装并重启 | `NOT_EXECUTED` |
| P-5 数据保持（自动升级路径） | `NOT_EXECUTED` |

**任何文档、收据、仪表盘不得把这些项改写为 `PASS` 或 `ACCEPTED` 以外的表述。**

### 2. 风险接受的范围与主体

| 项 | 内容 |
|---|---|
| 接受方 | 项目维护者 |
| 接受的客体 | 本次公开版 Electron **自动下载 / 自动安装 / 重启 / 自动升级路径上的数据保持**链尚未完整验证 |
| 决定日 | 2026-10-26 |

### 3. 决定的作用域

本决定**仅**针对 `v26.10.1` **公开后的验证义务**，属对原政策 §五 的**一次性**补充处置：

- 不修改、不撤销 `26.10.1-policy-exception.md` 的正文；
- **不追溯宣称 §五 已履约**；
- 不改变任何已记录的测试事实（`S1_PASS` / `D1_PASS_WITH_GAPS` / `NOT_EXECUTED_IDENTITY_GUARD` 均保持原样）；
- 不授权修改 Hotfix、重建安装包、替换已发布资产、或开展新的测试。

### 4. 复核与即时触发

| 项 | 规则 |
|---|---|
| **首次复核日** | **2026-11-02**（检查一周内的安装、更新、数据异常反馈） |
| **即时触发（无需等复核日）** | 任一可信报告：① 自动更新失败；② 安装目录异常；③ 启动故障；④ **数据损坏** |
| 高影响事件的特别规则 | **数据损坏只要有一个可信案例即立即排查**，不等多个反馈 |
| 触发后的动作 | 重新开启 P-2~P-5 验证，并按 §六 的 fix-forward 规则处置 |

### 5. 不得自动继承到下一版

**`26.11.0` 正式发行门禁中，必须重新审查「从已发布版本到新版本的完整更新路径」。**

本文件**不构成** `26.11.0` 的豁免依据，也不得被引用为「自动升级链已经通过」。
26.11.0 如仍无法完成该验证，须**单独**作一次风险裁决，不得默认复用本文。

### 6. 无反馈 ≠ 验证通过

本项目**没有产品遥测**，GitHub Issues **不是**主动故障探测系统。

- 「N 天没有收到 Issue」只能说明**没有收到报告**，不能说明升级链工作正常；
- **明确禁止**以「30 天无 Issue」或任何时间阈值自动把 P-2~P-5 记为 `PASS` 或「已关闭」；
- 该技术证据缺口的关闭，只能通过**实际执行验证**或**后续版本的正式门禁裁决**。

> 这一条是本文件与「等 30 天看看」的关键区别：安全 Hotfix 的目标是让旧版用户**真正拿到补丁**；
> 若自动更新下载失败而用户既不查日志也不提 Issue，被动等待无法发现。
