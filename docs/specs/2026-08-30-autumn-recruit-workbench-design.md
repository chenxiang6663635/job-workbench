## 1. 定位与目标

把现有的 82 份求职资产（5 份事实卡、68 份手册文档、6 份 PDF、1 份 HTML 模板、1 个 PowerShell 脚本）从"备考资料库"升级为"可运转的秋招工作台"，覆盖 JD 解析、简历工坊、面试准备、投递追踪、知识库构建五个模块。

核心判断：内容资产层已经完成，本方案的工程量集中在命令定义、数据契约与五个小脚本，不开发 Web 应用、不引入数据库、不配置远程仓库。

一期目标（1–2 天可用）：拿到"看到一份 JD → 判定投不投 → 生成对应简历 PDF → 归档 → 记入追踪表 → git 提交"的完整闭环。
二期目标：把 03_面试准备 与 04_知识库 从"文件堆"变成"可被命令按需组装的复习包"。

## 2. 架构：四层，逻辑在 prompt 里

最关键的一条原则：**判断由 AI 做，脚本只做 IO 与校验**。JD 评分不是 Python 算出来的，是 AI 读了 JD 原文与候选人档案后填进解析卡的；Python 只负责校验加总是否自洽、套阈值出结论、并在权重或词典变更后批量重算历史 JD。收益是改评分标准不用改代码，只改 Markdown。

| 层 | 技术 | 说明 |
|---|---|---|
| 交互层 | `.codebuddy/commands/*.md` 四个斜杠命令 | 工作流定义，不含业务逻辑代码 |
| 数据层 | Markdown（82 份）+ CSV（追踪表）+ 归档目录 | 全部纯文本，git 可 diff，Excel 可直开 |
| 逻辑层 | 5 个 Python 脚本 | Python 3.8 兼容，零第三方依赖（PDF 校验复用已装的 pypdf 5.9.0） |
| 版本层 | 本地 git | 首次提交现有 82 份，第二次提交重组结果 |
| 领域知识层 | `.codebuddy/skills/recruit-coach/SKILL.md` | 评分标准、诚实红线、话术纪律 |

环境已核实：Python 3.8.19（conda-forge）、pypdf 5.9.0、Chrome 与 Edge 均在本机标准路径。脚本不得使用 3.9+ 语法（禁用 `dict | dict`、`list[str]` 等运行时注解）。

## 4. 数据契约

### 4.1 候选人档案 `CODEBUDDY.md`

AI 每次会话自动读取，是评分的基线。分为四节：

**能力分层**
- Primary：制冷循环、传热与流体、风水系统、HVAC 控制
- Secondary：EnergyPlus 与 CFD 工况运行、Python 数据分析、现场施工协调
- Weak：液冷工程交付、数据中心运维

**硬门槛事实**（以下 6 项需本人首次填写，脚本与命令在缺失时一律按 fail 处理并提示，绝不猜测）
最高学历、毕业届数、专业方向、CET-4 成绩、CET-6 成绩、可接受城市列表。

**经验资产**（对应 JD 评分的"经历匹配"维度）
- 项目二：VRF+DOAS 组合节能，DOAS 焓差边界，EnergyPlus/CFD 工况运行，分区人数→新风需求→阀开度控制，X%（必须表述为"研究案例显示"）；SCI：某能源类期刊（卷期略）
- 项目一：传感数据缺失下的降级与轻量化探索（只讲"已验证结论 vs 探索候选"，不称已部署）
- 某商业综合体实习：冷源 2×900RT 离心机 + 1×400RT 螺杆机、5+5 水泵、5 冷却塔、PAU/AHU+FCU、供热链、免费冷却板换、Q=ṁc_pΔT 验证

**全局纪律**：见第 8 节，逐条照抄。

### 4.3 追踪表 `05_投递追踪/tracker.csv`

UTF-8 with BOM（`utf-8-sig`），保证 Excel 直接打开中文不乱码。字段顺序固定：

| 序号 | 字段 | 取值约束 |
|---:|---|---|
| 1 | id | `A001` 起递增，不复用 |
| 2 | 公司 | 文本 |
| 3 | 岗位 | 文本 |
| 4 | 方向 | datacenter / hvac / other |
| 5 | 批次 | 提前批 / 正式批 / 补录 |
| 6 | 来源 | 应届生求职网 / 牛客 / 企业校招官网 / 学校就业网 / 内推 / 其他 |
| 7 | 截止日期 | YYYY-MM-DD 或空 |
| 8 | 投递日期 | YYYY-MM-DD 或空 |
| 9 | 当前阶段 | 见下方枚举 |
| 10 | 下次动作 | 文本 |
| 11 | 下次动作日期 | YYYY-MM-DD 或空 |
| 12 | 简历版本 | hvac / datacenter / 自定义 |
| 13 | 评分 | 0–100 整数 |
| 14 | 归档目录 | 相对路径 |
| 15 | 备注 | 文本 |

阶段枚举：`待投 → 已投 → 笔试 → 一面 → 二面 → 三面 → HR面 → offer → 签约`，终态 `已挂` / `已放弃`。

`批次` 字段是 2027 届秋招最关键的组织维度——提前批、正式批、补录三批并行，且同一公司不同批次可重复投递。社招模型里没有这个概念，因此必填。

## 5. 评分框架

### 5.1 Eligibility Gate（前置，不通过则不打分不写材料）

判定顺序：学历 → 专业 → 届数 → 英语 → 城市。任一项 fail 立即输出"不建议投递 + 原因"并停止后续流程，不生成解析卡的评分子节，不调用 `/apply`。判定所需事实全部取自 `CODEBUDDY.md` 的"硬门槛事实"小节；任一字段缺失时按 fail 处理并在输出中显式提示"请补齐 CODEBUDDY.md 中的 X 字段"，禁止猜测。

城市为 pass/fail，不参与加权；而"长期驻场 / 倒班 / 长期出差"这类工作形态问题不在此判定，归入"培养与稳定性"维度扣分，两者分工明确。

### 5.2 四个维度

**技术匹配 30 分**：按 `config/direction_*.md` 中的 Primary / Secondary / Weak 三级词典比对 JD。命中 Primary 每项 3 分、Secondary 每项 1.5 分，上限 30。命中 Weak 不直接扣分，但必须登记到"命中 Weak"并触发风险提示——Weak 项意味着面试中会被追问而你无法用真实经历回答，需在结论中给出诚实的桥梁话术建议。

**经历匹配 25 分**：逐条比对三条经验资产（项目二、项目一、某商业综合体实习）与 JD 职责。每条能对上 JD 核心职责的给 8–10 分，只能侧面支撑的给 3–5 分，完全无关的 0 分。上限 25。打分依据必须回到 `00_事实库` 核对，不得以解析卡的概述为准。

**方向契合 30 分**：锚定"冷却系统与热管理"这一主线，按 `config/direction_*.md` 的锚点表取值。

数据中心方向锚点：数据中心冷却 / 热管理 25–30；IDC 基础设施 / 机房暖通 22–28；液冷产品研发 20–26；建筑能源管理 12–18；非热方向 0–8。

HVAC 方向锚点：空调制冷系统研发 / 设计 25–30；暖通设计 / 工程 22–28；建筑节能与咨询 18–24；设备厂商技术支持 15–22；非暖通 0–8。

**培养与稳定性 15 分**（本维度替换原框架的文化契合）：

| 分值 | 判据 |
|---|---|
| 13–15 | 明确校招培养体系（导师制 / 轮岗 / 培训体系），岗位为技术核心岗，无强制长期驻场或倒班 |
| 9–12 | 校招岗但培养体系未明示，岗位偏技术，工作地可接受 |
| 5–8 | 培养信息缺失；岗位偏运维或现场执行；或需长期出差 |
| 0–4 | 劳务派遣 / 外包、非技术岗、强制倒班或驻场不可接受 |

替换理由：校招 JD 中的"文化"大多为空话，AI 从 JD 文本判断文化契合的可靠度很低；而"这个岗位是否把我当培养对象""工作形态是否长期可持续"既可从 JD 文本判断，也对你的决策影响更大。

### 5.3 阈值与结论档位

| 总分 | 档位 | 动作 |
|---|---|---|
| 75–100 | 强烈建议投 | 立即进入 `/apply` |
| 60–74 | 建议投 | 进入 `/apply` |
| 45–59 | 斟酌 | 先看缺口能否在一周内补，再决定 |
| 30–44 | 大概率跳过 | 除非有额外信息（内推、岗位调整），否则不投 |
| 0–29 | 不投 | 停止 |

### 5.4 方向配置与第三类岗位

`/jd` 通过 `--direction` 加载 `config/direction_datacenter.md` 或 `config/direction_hvac.md`。两个方向共用同一套权重与流程，差异仅在关键词词典与方向锚点——这正是"HVAC 版 vs 数据中心版"从两条独立路线收敛为一套体系的两个配置的原因。

**不建第三个配置文件**。遇到两个方向之外的岗位（如建筑节能咨询、热管理硬件）时，`/jd` 回退到数据中心配置，并在解析卡末尾追加一行：`⚠️ 该岗位不属于两个预设方向，评分基于数据中心配置计算，结论仅供参考。` 这是 YAGNI 的取舍，真出现第三类岗位的常态化需求时再补配置文件。

## 6. 命令定义

### 6.1 `/jd` — JD 解析与评分

输入：JD 文本或文件路径，可选 `--direction=datacenter|hvac`（缺省时由 AI 依据 JD 内容判断并显式说明判断依据）。

流程：
1. 建 `01_岗位池/<公司>_<岗位>/`，将 JD 原文落盘为 `JD原文.md`（保留原始文本，不改写、不摘要）
2. 跑 Eligibility Gate，不过则写出不完整解析卡（只填基本信息与硬门槛）并终止
3. 过则生成完整解析卡，逐维打分，评分依据必须引用 JD 原文措辞与 `00_事实库` 条目
4. 调 `python tools/jd_score.py <解析卡路径>` 校验加总自洽并取结论档位
5. 回填解析卡的"结论"小节，输出档位与下一步建议

### 6.2 `/apply` — 生成投递包并归档

1. 读解析卡，确认方向与简历版本映射（datacenter → 数据中心冷却版，hvac → HVAC 空调制冷版）
2. 按需微调简历，只改四处：求职方向、Profile、技能顺序、项目表述；**项目事实一律不动**
3. 调 `python tools/resume_build.py --version <版本>` 生成 PDF 并做 ATS 校验
4. ATS 校验不通过则中止并报告具体失败项，不归档
5. 通过后归档到 `05_投递追踪/applications/<公司>_<岗位>/`：JD 原文快照、投递版 PDF（文件名带日期）、空白面试记录
6. 调 `python tools/tracker.py add ...` 写入追踪表，取回 id
7. 生成提交信息 `apply: <公司> <岗位>` 并列出待提交文件清单，**交由用户确认后由用户执行提交**；命令自身不得自动 `git commit`

### 6.3 `/track` — 追踪表查改

子命令直接透传给 `tools/tracker.py`：`add` / `update` / `list` / `show`。常用：`/track list --due-within 7`（七天内截止）、`/track list --stage 笔试`。需要可视化时调 `tools/report.py` 生成 Markdown 看板。

### 6.4 `/resume` — 单独跑 PDF 流水线

不经过 JD，直接重建一版或全部简历 PDF 并校验，用于改简历后的回归。

## 7. 脚本接口

全部使用 Python 3.8 兼容语法，仅依赖标准库；`resume_build.py` 可选依赖 pypdf（已装）。所有脚本以退出码 0 表示成功、非 0 表示失败，输出到 stdout 的 Markdown 片段供命令直接回填。

### 7.1 `tools/fix_links.py`

一次性工具，处理目录重组的断链。内置旧路径→新路径映射表，`--apply` 写入（缺省为 dry-run，只打印将要修改的文件与链接数）。重写 Markdown 中的相对链接 `](...)`，不动绝对路径与 URL。运行后需人工抽检知识词典的互链。

### 7.2 `tools/jd_score.py <解析卡路径> [--direction datacenter|hvac]`

解析 `## 评分` 小节的 `key: value` 行。校验三项：各维度分子 ≤ 分母、四项分子之和 = 总分、门槛结论字段存在。校验通过后按第 5.3 节阈值输出档位与建议动作。任一项不自洽则退出码非 0 并指出具体字段。

### 7.3 `tools/resume_build.py [--version hvac|datacenter|all] [--out DIR]`

探测 Chrome 或 Edge（沿用现有 `build_resume_pdf.ps1` 的四个候选路径），headless 打印 HTML 为 A4 PDF。随后做 ATS 校验，三项全部通过才算成功：PDF 页数为 1；pypdf 可提取文本且长度 ≥ 800 字符；若 `config/ats_required_facts.txt` 存在，则逐行检查其列出的关键事实关键词是否出现在提取文本中，缺失项逐一列出。该文件不存在时跳过第三项并输出提示，不视为失败——一期可先不建该文件，待你从 `00_事实库` 整理出关键事实清单后再补。

本脚本全面取代现有的 `build_resume_pdf.ps1`（Chrome 探测路径、HTML→PDF 映射、页数校验逻辑均从该脚本迁移）。原 PS1 脚本随目录重组移入 `99_归档/`，不再维护，避免两套 PDF 生成逻辑并存。

### 7.4 `tools/tracker.py add|update|list|show`

统一操作 `05_投递追踪/tracker.csv`。

- `add`：按 4.3 节字段写入，自动生成递增 id，校验方向与批次枚举、日期格式、评分范围
- `update --id A001 --字段 值`：只允许更新阶段、下次动作、下次动作日期、备注、评分五项；公司与岗位不可改（改则需新建记录并作废原记录）
- `list`：`--stage` / `--direction` / `--batch` / `--due-within N` 过滤，按下次动作日期升序

## 11. 风险与取舍

**重组断链**：82 份文档间存在相对路径互链，`fix_links.py` 只能处理 `](相对路径)` 形式；正文里以纯文本提及的旧路径（如"见 02_作战手册/行为面/"）无法自动改写，需 `search_content` 全量扫一遍再手工处理。这是选择"原地重组"方案的既定代价。

**Python 3.8 环境**：语法受限，脚本不得使用 3.9+ 特性。若后续需要更现代的写法，先升级解释器，不要为了语法糖引入兼容层。

**仅本地 git**：无远程备份，磁盘故障即丢失。若后续改变主意，建议优先选本地裸仓库镜像（同机另一磁盘 `git clone --mirror`），而不是推到第三方平台——简历含姓名、照片与联系方式。

**脚本数量控制**：五个脚本是上限，不随功能增长继续加。新需求优先改成命令里的 prompt 步骤，只有出现"必须可复现、可批量重算、或涉及二进制处理"的需求时才新增脚本。
