# 简历模块数据驱动改造：实测结论与方案（2026-09-02）

## 一、实测结论（已用真实命令验证，非推断）

### 1. 纸型：`--print-to-pdf` 读取 CSS `@page size`（与调研推断相反）

用本机 Chrome 实测两个最小 HTML：

```
无 @page 声明  → mediabox 612×792   = Letter
@page{size:A4} → mediabox 594.96×841.92 = A4
```

结论：**命令行 `--print-to-pdf` 实际读取模板的 `@page size`**，并非调研 agent 所称"不读 @page 默认 Letter"。调研的"默认 Letter"只在**模板未声明 @page** 时才成立。

现有 personal 简历（`resume_hvac.html` 等）第 7 行均显式声明 `@page { size: A4; ... }`，故实测其 PDF mediabox 全部为 A4（594.96×841.92）。

**渲染方案硬性约定**：内置 HTML 模板必须显式写 `@page { size: A4; margin: ... }`。纸型问题靠模板约定解决，**无需 CDP `Page.printToPDF`，也无需 pypdf 后处理**。

### 2. 中文文本层可提取性：可用，无乱码

用 pypdf 提取现有 `某用户_简历_空调制冷HVAC_v1.2色块版.pdf`：
- 页数 1
- 可提取中文文本 **1895 字符**（无乱码，中文完整）
- 示例："求职意向：空调制冷 / HVAC 系统工程 · 能效优化与运行控制 / 专业概况 / …"

结论：Chrome headless 输出的中文 PDF 文本层可被 pypdf 正常提取，**不存在"提取乱码/空"的问题**。调研的工程推断得到实测佐证。现有简历 1895 字符远高于任何合理阈值，故 `MIN_TEXT_LENGTH` 从 300 提到 400–500 不会误判现有简历（预留空间充足）。

## 二、方案

**保持 Chrome headless 渲染管线**（实测确认稳定、中文可用、免环境）。改造目标是**消灭"Markdown 草稿 + HTML 生成源"双份维护**，让内容与版式解耦。

```
数据 resume_<版本>.json   （结构化内容，唯一需维护的文件）
        ↓  render 子命令
内置 HTML 模板（放 template，含 @page A4）
        ↓  resume_build.py 现有打印
临时 HTML → Chrome headless → 简历_<版本>.pdf → pypdf ATS 校验
```

`resume_build.py` 新增 `render` 子命令：读 JSON → 套内置模板渲染出 HTML → 交给既有打印/校验。**无子命令时保持现有行为（直接打手写 HTML）不变**，向后兼容。脚本数仍为 6，不新增第 7 个。

## 三、关键工程权衡：数据化 vs 现有精细版式（需用户确认）

本批改造前实测了真实简历 `resume_hvac.html`（7.57 KB）——它的排版是**高度精细的手写 HTML**：

- 条件性结构（专业概况、教育经历多条不同样式、项目/工程实践/科研成果/奖项多区块类型）
- 内联高亮 `<strong>`（关键数字 X%、2×900RT 等加粗）
- 精确 mm 布局（header 29.4mm、photo 21×29.4mm 绝对定位右对齐、period 左右 flex 对齐）
- SCI 标签、多行 justify 两端对齐

**一个通用 JSON schema + 单个内置模板无法无损复现这份版式**。任何"数据驱动 + 通用模板"的实现必然意味着：要么把版式抽象成模板可表达的形态（**现有视觉会劣化**，变成更规整但更普通的标准一页版式），要么保留当前手写 HTML 作为"高级模板"单独存在、数据驱动只服务"标准版式"。

存在两条路径，需要用户拍板（这决定 spec 的 schema 与模板设计深度）：

| 路径 | 版式 | 数据维护 | 工作量 | 适合 |
|---|---|---|---|---|
| **A. 数据驱动为标准版式，保留当前 HTML 作高级模板** | 现有精细版式无损保留（作为高级模板走老路）；新增标准版式走数据驱动 | 标准版改 JSON；高级版仍双份 | 中 | 要可复用、给普通用户用 |
| **B. 全量数据化，接受版式统一** | 所有简历统一为内置模板标准版式，现有 v1.2 色彩版作历史归档 | 只改 JSON，单份 | 中大 | 要彻底消灭双份，接受外观变化 |
