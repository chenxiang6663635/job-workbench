# P0–P3 四批实施：设计与验收记录

日期：2026-09-03 起，2026-09-04 全部落地
来源：`docs/research/research_report_next_features.md`（功能差距分析）中的 13 项空白

## 总原则

- **分四批、每批独立可验收**，节奏可停
- 严守 6 个脚本上限：新能力全部落在现有脚本的子命令或纯 Web 路由
- 面试/联系人/Offer 一律独立 CSV，**绝不加 tracker.csv 列**（保住主表「一行一岗位」的当前状态快照语义）
- 诚实红线是产品核心：措辞设计（召回 vs 编造、拒绝 vs 失败）在代码与 UI 中强制区分

## P3 长期资产（已落地）

| 能力 | 落点 | 要点 |
|---|---|---|
| 周期复盘 | `report.retrospective()` + Dashboard 区块 | 转化率从 history **重建「到达过」的阶段集合**（原值/新值都是到达证据），绝不用当前存量冒充；停留报**中位数**（重建阶段时间线，进入=首次变更，离开=下次变更）；失败归因按「状态原因」聚合 |
