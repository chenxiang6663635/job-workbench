# job-workbench · Usage Guide

Everything you need to take the workbench from zero to running, plus how to use it day to day.

If something breaks, go straight to the FAQ at the end — it covers the traps already hit (blank screen, ports taken by another process, and so on).

## I. One-time environment setup

Do this once. Skip it if your environment is already set up.

### Required

| Software | What it is for | How to check |
|---|---|---|
| Python 3.8+ (conda env) | Backend and CLI scripts | `python --version` |
| Node.js 18+ | Frontend build | `node --version` |
| Chrome or Edge | PDF generation (headless rendering) | Usually already present |

### Install dependencies (once each)

```bash
# Backend (fastapi/uvicorn/pydantic are pinned to Python 3.8-compatible versions)
cd <repo>\web\backend
pip install -r requirements.txt

# Frontend
cd <repo>\web\frontend
npm install
```

### Initialise your workspace (skip if you already have `personal/`)

```bash
python tools/init_workspace.py --target personal --domain hvac-cooling
```

If you just want to see what it looks like without filling in any real information, use `--demo`:

```bash
python tools/init_workspace.py --target demo --demo
```

That also lays down a full set of placeholder data (8 applications / 3 interviews / 2 contacts / 1 offer / 2 parsed JD cards / 1 resume). Every company and person name is fake, so you can click around or take screenshots safely; the `software-backend` domain profile is installed by default because the demo data's "direction" field depends on it. Once it is running, pick `demo` from the workspace dropdown in the top-right corner.

## II. Day-to-day startup: the web UI

### Option 1: one command (recommended)

```powershell
cd <repo>\web
.\start.ps1
```

The script clears any occupied ports, starts the backend (8765), starts the frontend (5173), waits until both are ready, and opens your browser.

**To stop it**: close the console window the script runs in — both services stop together.

### Option 2: manual startup (when you need backend logs)

Open two terminals:

```bash
# Terminal 1: backend
cd <repo>\web\backend
python -m uvicorn main:app --port 8765

# Terminal 2: frontend (on Windows you MUST use npm.cmd; plain npm fails silently)
cd <repo>\web\frontend
npm.cmd run dev
```

### Addresses

| Address | What it is |
|---|---|
| http://localhost:5173 | **The workbench UI (this is the one you use)** |
| http://localhost:8765/docs | Backend API docs (generated by FastAPI) |

> The frontend proxies `/api` to 8765, so your browser only ever talks to 5173.

### Option 3: double-click the exe (no environment needed; good for handing to someone or a quick look)

The build output lives in `web/backend/dist/job-workbench-backend/` — double-click `job-workbench-backend.exe` inside it:

- **Nothing is running yet** → it starts the backend and opens a browser (the black console window is the service log; closing it stops the service)
- **Already running** → it just opens the browser, without starting a second service
- **The port is taken by another program** → you get a plain-language message and the window stays open (it does not flash and vanish)

> ⚠️ **The exe is a "clean distribution" and does not read your personal data.** The portable workspace sits next to the exe (`personal/`, empty by default) — that is deliberate, so your job-search data never travels with an installer. **Use option 1 or 2 for your own day-to-day work** (data lives at the repo root); use the exe to validate a build or to hand to someone else. If you insist on pointing the exe at your own data, set `JOBWS_DATA_DIR` to the repo root (not recommended — it forks your data).

Rebuild the exe:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_backend_exe.ps1
```

### Desktop installer (Electron shell, since v0.1.1)

If you would rather not set up an environment at all, grab `job-workbench-setup-*.exe` from the [latest release](https://github.com/chenxiang6663635/job-workbench/releases/latest) (an Electron window plus a packaged backend; install it and run). Where data goes: the installed version uses `%APPDATA%\job-workbench\personal\`; the portable version (a `portable.txt` next to the backend exe) uses `personal\` beside the exe — **uninstalling the installed version does not touch the data in %APPDATA%**.

Rebuild the installer in one command (frontend dist → PyInstaller backend exe → NSIS):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_desktop.ps1
```

The output is `web/electron/release/求职工作台 Setup <version>.exe`. Smoke test: `Setup.exe /S /D=<dir>` installs silently, launch it, then check `http://127.0.0.1:8765`.

## III. The seven pages of the web UI

### Dashboard (home)

This is what opens first. It answers three questions: how many companies have I applied to, how many are still in flight, and what needs doing in the next seven days.

- Four stat cards at the top: total applications / in progress / to-do in 7 days / past deadline (click to drill into the tracker)
- Application funnel: how many people at each stage (to apply → applied → written test → … → signed); click a bar to drill into that stage
- **Needs action**: active roles with an unhealthy status (urgent / overdue / stalled), each with a concrete reason; click to drill in
- To-do in 7 days: records whose next-action or deadline falls within the next 7 days (one click to postpone by 7 days)
- Past deadline: records still sitting at "to apply" whose deadline has passed (red)
- Silent reminder: active roles with no progress for a long time (over 14 days by default)
- **Cycle review**: stage conversion rates (rebuilt from the timeline), median days spent per stage, failure attribution and **failure clustering**

### Tracker

A table of every application. Six things you can do:

- **Filter and search**: by stage / direction / batch, plus keyword search over company, role and notes
- **Sort**: by next-action date / score / days in stage / **health** (urgent > overdue > stalled > normal; hover the badge for the reason)
- **Change stage**: click the "current stage" dropdown on a row to change it (to apply → applied → written test → …); it saves automatically
- **Add, or import in bulk**: "Add application" at the top right for one at a time; "Bulk import" to paste or upload a CSV, which first shows a diff preview (added / duplicate / error rows in different colours with line numbers and reasons) and blocks submission while any row has an error
- **Status reason**: edit in place per row; **moving to "declined / gave up" requires a reason**, and once in either of those states the stage can no longer be changed (to apply again, create a new record)
- **Row expansion**: see that record's change timeline and how many days it has sat in the current stage

**Two rules (shared by CLI and web, enforced automatically):**
1. **Terminal states do not roll back**: after "declined / gave up", the current stage is locked; only the status reason and notes stay editable
2. **Deduplicate by company + role**: a duplicate entry is blocked and points you at the existing record id (applying again *after* being declined is allowed)

> The options in the direction dropdown come from the domain profiles installed in your workspace (`config/directions/`), not from a hardcoded list.

### Job pool

Manage the roles you have looked at. Each card shows company_role, its score and its tier.

- **New role**: paste the full JD (responsibilities + requirements) and it is archived verbatim; or paste **a URL and let it fetch the page** (pages that need a login, block scrapers or render with JS produce an explicit "paste it manually" message — it never pretends to succeed)
- **Open details**: JD on the left, parsed card on the right
- **Eligibility gate (pinned above everything)**: the "hard eligibility" card at the top of the parsed card is shown *before* the score — pass (green) / fail (red) / to confirm (amber). **A fail is pinned and highlighted in red**, and the score becomes secondary information (it means you are not eligible — do not apply)
- **Score drill-down**: each of the four dimensions (technical / experience / direction / growth) expands to per-item hits, each with a capability tier (Primary/Secondary/Weak), an **evidence label** (exact / vague / semantic badge) and a hit explanation. If you want to know "why this score", open it
- **Resume gap panel**: the gaps between this JD and your resume, split into "recallable" (it exists in your master resume) and "real gaps" (only new experience can fill them)
- **Parsed card**: the score is produced by the AI inside CodeBuddy and written to `解析卡.md`; this page renders the four dimension bars, total score and tier
- Roles without a score show "no parsed card yet" plus instructions — **the web UI does not score anything**; scoring is the AI's job

### Resume workshop

**Two modes:**

- **Standard layout** (data-driven): structured form on the left, live A4 preview on the right; create versions right on the page; after generating a PDF it reports the ATS check and paper-size check, with an overflow guard
  - **One-click import**: upload a PDF / Word (.docx) / Markdown / plain text and it is extracted into structured fields. **Extraction, not generation**: fields the model did not find are marked yellow, suspected fabrications red, and nothing is written until you confirm section by section
  - **AI rewrite suggestions**: a BYOK model only rephrases existing facts; suggestions that fail the anti-fabrication guardrails cannot be accepted
  - **Export Word**: a dependency-free `.doc`, handy for pasting text into online application systems (the PDF is the source of truth for layout)
- **Advanced template** (hand-written HTML, precise layout): read-only viewing and one-click generation

At the bottom there is also a **version lineage**: which resume version went to which roles, and how far each got.

### Progress

The main arena after you apply. Four sub-tabs:

- **Interviews**: three-part record (question → answer points → retro); anything still pending within 48 hours is highlighted amber; one-click export to `.ics`
- **Question bank**: questions you have been asked, grouped by company + role, with keyword search — read what this company already asked you before the next round
- **Contacts**: follow-up cadence for recruiter contacts, amber when overdue, one-click "contacted"
- **Offer comparison**: known facts of several offers side by side. **Side by side only — no recommendation**

### Library

Read-only view of your own asset files (maintained by the CLI/AI): fact card source text, inline preview of resume-related files.

### Settings (Provider)

The "Settings" page in the nav configures your AI provider (BYOK, bring your own key):

- **Base URL**: an OpenAI-compatible endpoint (including `/v1`, e.g. `https://api.orcarouter.ai/v1`)
- **API Key**: stored locally only; the UI shows just the masked last 4 characters
- **Test connection**: calls `{base_url}/models` to verify the key and list models
- **Data and privacy**: export everything as a zip, snapshot backup to the system user directory, open the data directory, no-telemetry statement

> By default the AI judgement in this workbench is done by your AI CLI (CodeBuddy and friends); the provider is an optional BYOK enhancement (used for resume import and AI rewrite).

## IV. Putting the AI to work: the jwb-jd / jwb-apply workflows

The web UI is for looking and recording; **judgement belongs to the AI**. Talk to it in natural language inside CodeBuddy:

### Parse a role (jwb-jd workflow)

Paste the JD, or say "parse this JD". The AI will:

1. Save the JD text under `personal/01_岗位池/<company>_<role>/`
2. Run the hard eligibility filter (degree → major → cohort → English → city) against `personal/AGENTS.md`
3. If it passes, score four dimensions (technical 30 / experience 25 / direction 30 / growth 15) and cross-check against your fact cards
4. Verify the total and output a tier (75+ apply strongly / 60–74 apply / 45–59 think about it / below 45 do not apply)

**Failing a hard requirement stops everything** — no score, no materials. For example a role with a hard language requirement is blocked by your own language red line.

### Generate an application package (jwb-apply workflow)

Say "generate an application package for role XX". The AI will: pick the resume version for that direction → adjust four places as needed (project facts are never touched) → generate the PDF → run the ATS check (page count / text layer / key facts) → archive under `05_投递追踪/applications/` → write to the tracker → list the changes and hand them to you to confirm before committing to git.

### Update progress (jwb-track)

After an interview, say "move XX to first round", or just use the dropdown in the tracker.

### Rebuild the resume PDF after edits (jwb-resume workflow)

Say "rebuild the resume PDF", or from the command line:

```bash
python tools/resume_build.py --workspace personal --version hvac
```

## V. CLI quick reference (when you would rather not use the web UI)

Run every command from the repo root. `--workspace personal` can be omitted (it is the default).

```bash
# Tracker
python tools/tracker.py list                        # every record
python tools/tracker.py list --due-within 7         # due within 7 days
python tools/tracker.py list --stage 笔试           # filter by stage
python tools/tracker.py add --company "某公司" --role "岗位" --direction hvac --batch 正式批 ...
python tools/tracker.py update --id A001 --stage 一面 --next "准备口述" --next-date 2026-09-10
python tools/tracker.py history --id A001           # change timeline
python tools/tracker.py import --file 待导入.csv --dry-run   # bulk CSV import (preview diff only)
python tools/tracker.py import --file 待导入.csv             # write, once the preview is clean
python tools/tracker.py interview add --app A001 --round 一面 --questions "..."   # interview record
python tools/tracker.py contact add --name "张工" --app A001   # recruiter contact
python tools/tracker.py offer add --company "某公司" --monthly "..."  # offer facts
python tools/tracker.py check                       # schema self-check (quarantines broken files)

# Application funnel report (Markdown, incl. cycle review and failure clustering)
python tools/report.py --stdout

# Resume PDF + ATS check
python tools/resume_build.py --workspace personal            # all versions
python tools/resume_build.py --version hvac                  # one version
python tools/resume_build.py render --workspace personal     # data-driven standard layout

# JD parsed-card score validation
python tools/jd_score.py "personal/01_岗位池/<dir>/解析卡.md" --domain hvac-cooling --direction hvac
python tools/jd_score.py --gap --resume hvac "personal/01_岗位池/<dir>/解析卡.md"   # JD↔resume gaps
```

> The stage names above (`笔试`, `一面`, …) are the actual values written into your data files, which is why they appear in Chinese. They are validated against a fixed list (`STAGES` in `tools/tracker.py`), so they cannot simply be renamed to English.

## VI. Where your data lives, and how to back it up

**All data is plain text**, under `personal/`:

| Directory | Contents |
|---|---|
| `00_事实库/` | Project/internship fact cards — the single source of truth |
| `01_岗位池/` | One directory per role: the JD text + parsed card |
| `02_简历工坊/` | Resume markdown + HTML templates + generated PDFs + photo |
| `03_面试准备/` | Self-intro, project pitches, question bank, behavioural stories, retros |
| `04_知识库/` | 30 knowledge dictionaries |
| `05_投递追踪/` | `tracker.csv` + `history.csv` (change timeline) + `interviews` / `contacts` / `offers.csv` |
| `AGENTS.md` | Your profile: hard-requirement facts, honesty red lines |

**Backup (important)**: all of `personal/` is gitignored — **git does not track your data**, and a clone of the repo carries none of it. The two supported ways to back up:

1. **Settings → "Back up now"**: snapshot to the system user directory (outside the workspace; one click; recommended)
2. **Settings → "Export everything as zip"**: a complete workspace you can take anywhere

> ⚠️ Sharing the repository itself is safe — `personal/` is not in it. **Never send the `personal/` directory to anyone** (it holds your name, photo and contact details).

## VII. FAQ

### localhost:5173 is blank / will not connect

Work through these in order:

1. **Is the service alive?** Restart with `cd web && .\start.ps1` (it clears the ports for you). Vite is a foreground process — if the terminal that started it is closed, the service is gone. This is by far the most common cause
2. **Is the browser caching old JS?** Force a reload with `Ctrl + F5`
3. **Still blank?** The app now has an ErrorBoundary, so a crash shows an error message instead of a blank page. Open the Console (F12) and send me the error

### The startup script errors

`start.ps1` locates the repo root with three fallbacks (argument → script location → walking up for `AGENTS.md`). If it says it cannot locate the repo root, run it from inside the repo, or pass the path explicitly:

```powershell
.\start.ps1 -RepoRoot <repo dir>
```

### npm does nothing

On Windows you must start the frontend manually with `npm.cmd run dev`. A plain `npm run dev` can fail silently depending on how it is invoked (no error, and nothing listens on the port).

### The port is taken

`start.ps1` frees 8765/5173 automatically. To do it by hand:

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

### A job card in the UI has no score

A score needs two things: the `解析卡.md` must exist **and** its four dimensions must add up to a consistent total (validated by the `jd_score` rules). If you hand-edited a parsed card and broke the format, the UI treats it as "not scored". Run `python tools/jd_score.py <path to parsed card>` to see exactly what does not add up.

### CSV opens as gibberish in Excel

It should not — files are written with a UTF-8 BOM (`utf-8-sig`). If it really is garbled, some other tool rewrote the encoding; tell me and I will fix it.

### Double-clicking the exe does nothing

With `console=True`, a black window that flashes past means **it failed at startup**. Causes and what to do:

1. **Port taken** → the exe now prints a clear message and keeps the window open (unless your antivirus interferes). First check who holds the port: `Get-NetTCPConnection -LocalPort 8765 -State Listen`
2. **A freshly built exe being empty is expected** — see "Option 3" above (the exe is a clean distribution; it does not read the repo-root data)

### The page title says "Vite + React + TS"

That is a stale artifact from an older build or a cached bundle. Force-reload with `Ctrl+F5`; if it persists, rebuild the frontend (`cd web/frontend && npm.cmd run build`) and restart the backend. The **new** correct title is 「求职工作台」.

### .ps1 scripts throw ParserError / mojibake

A `.ps1` containing Chinese must be saved as **UTF-8 with BOM**. Save it without the BOM and Windows PowerShell 5.1 decodes it as GBK, producing syntax errors. Both scripts (`start.ps1`, `build_backend_exe.ps1`) ship with a BOM — **do not strip it** if you edit them.
