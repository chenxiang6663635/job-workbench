# 领域插件四件套：模板与示例

供生成候选时套用。格式要求以 `jobws lint domains` 的校验为准——它是契约的
可执行版本；本文件给最小可用模板与写法要点。

## 1. profile.md

以身份表开头，**插件 ID 必须与目录名一致**（校验器会核对）：

| 项 | 值 |
|---|---|
| 插件 ID | `<domain-id>` |
| 名称 | 领域中文名 |
| 适用人群 | 哪些专业 / 背景的候选人在用 |
| 覆盖岗位 | 这个插件服务的岗位类型 |
| 内置方向 | `方向a`（说明）、`方向b`（说明） |
| 建立日期 | YYYY-MM-DD |

其后自由组织：结构说明、维护记录等。身份表由使用者口述、AI 不代填不猜测。

## 2. lexicon.md

三级分层，每级一个 `## <层名>` 小节；**层名必须以 Primary / Secondary / Weak
开头**（评分侧按前缀识别，换成别的字样会让整层词条永远匹配不到）：

    ## Primary（3 分/项）

    词条一、词条二、词条三
    词条四、词条五

    ## Secondary（1.5 分/项）

    词条六、词条七

    ## Weak（登记不扣分，触发风险提示）

    词条八、词条九

写法要点：

- 每行用**顿号**分隔词条；三层都必须有词条（缺层不报错，只是该层匹配不到）；
- 分层的含义不是「会不会」，而是**「能不能经得起追问」**：
  - Primary：能讲清原理、能回答两层以上追问；
  - Secondary：有实操经验、能支撑，但要谨慎表述边界；
  - Weak：只有知识性了解——命中不扣分但会触发风险提示；
- 生成候选时每个词附自检问题（如「这个词背后你交出过什么？」），
  由使用者逐条定层。

## 3. failure_keywords.txt

每行「类别=关键词1,关键词2」，`#` 开头为注释行：

    # 顺序敏感：更具体的类别写前面（例如先「学历门槛」再「竞争」）
    # 都没命中归入「其他 / 未归类」
    简历与匹配度=简历,匹配,经历不符,方向不符
    笔试与测评=笔试,测评,行测,机考
    面试表现=面试,一面,二面,终面,答不上
    竞争与名额=竞争激烈,名额,缩招,已招满

这是使用者自己的归因口径——初始给通用骨架，随实战校准。

## 4. directions/<方向>.md

每个方向一个文件，含三节：方向特有补充词 / 方向契合锚点表 / 维护记录。

    # 方向：<方向名>

    评分共用一套权重（技术匹配 30 / 经历匹配 25 / 方向契合 30 / 培养与稳定性 15），
    本文件只定义**方向特有补充词**与**方向契合锚点表**。

    共用词典见 `../lexicon.md`。

    ---

    ## 一、方向特有补充词

    ### Secondary 补充

    词条一、词条二、词条三

    ### Weak 补充（本方向尤其容易被追问）

    词条四

    ---

    ## 二、方向契合锚点表（30 分）

    按岗位名称与职责取最接近的一档，同档内按 JD 契合程度微调。

    | 岗位类型 | 分值 | 说明 |
    |---|---:|---|
    | 主线岗位 | 25–30 | 直接对口 |
    | 高度相关 | 22–28 | 需确认偏研发还是运维 |
    | 相关岗位 | 18–24 | 能力可迁移 |
    | 部分相关 | 12–18 | 只共享基础能力 |
    | 基本不匹配 | 0–8 | 不建议投 |

    岗位名称与职责不一致时，**以职责为准**。

    ---

    ## 三、维护记录

    | 日期 | 变更 |
    |---|---|
    | YYYY-MM-DD | 初版 |

锚点表的判据：**把该方向从「直接对口」到「基本不匹配」排 5–7 档**，每档一个
分值区间。区间数值由使用者逐档确认——AI 建议值只是起点，不代替判断。
