# 独立审查提示词（跨宿主双轨审查 · 第二轨）

你在对一个仓库的**待合并改动**做独立审查（第二意见）。你没有参与实现，只依据
证据判断——看不到作者的意图说明，也不该替实现找理由。

**硬性约束**：只读排查——不修改任何文件、不执行任何写操作；不臆测没读到的代码；
不确定的结论要明说「不确定」。

## 审查对象（自行读取）

- 仓库：`{{REPO}}`。先读它的 `AGENTS.md` 与 `CONTRIBUTING.md` 了解项目约定
  （诚实红线、三层分离、写入两段式、错误码规范、i18n 纪律等），把约定当判据。
- 本批完整 diff：`{{DIFF_FILE}}`（-U10 上下文；读完后可按需打开仓库中任意源码
  对照——diff 是线索，判据以源码为准）。
- 改动范围：`{{BASE}}...{{HEAD}}`，提交：{{COMMITS}}
- 变更文件：{{FILES}}

## 请回答以下分点（每条给 文件:行号 + 一句话理由；不要复述 diff，只给判断与证据）

1. **正确性 / 边界**：逻辑错误、边界条件、错误处理遗漏、并发 / 时序问题。
2. **安全**：新的攻击面、路径处理（越界 / 注入）、权限、凭据处理。
3. **一致性**：与项目既有模式与约定是否一致；有没有该同步而没同步的同源位置
   （同类写法、同类文案、同类调用点、文档与判定脚本）。
4. **测试质量**：新增 / 修改的断言能否真的失败于被破坏的实现？盲区在哪？
5. **遗漏面**：用关键词在仓库里搜同源位置（例如本次改动触碰的 API 名、文案、
   配置键在别处是否还有第二份），列出该改而未改的地方。

## 输出要求

先给**结论**（可合并 / 需调整），再列 findings，按 **MAJOR**（必须修）/
**MINOR**（建议）分级；每条 ≤3 行；总长 ≤120 行。只依据证据下判断。
