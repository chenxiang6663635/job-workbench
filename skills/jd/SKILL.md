# 解析 JD 并判定是否值得投递

**执行前必读**：工作区的 `AGENTS.md`（档案、硬门槛事实、自定义红线）与 `skills/recruit-coach/SKILL.md`（评分标准）。不读这两份不得开始评分。

## 流程

### 1. 建岗目录并存原文

在工作区的 `01_岗位池/` 下建 `<公司>_<岗位>/`，把 JD 原文完整落盘为 `JD原文.md`。

**保留原始文本，不改写、不摘要、不翻译。** 后续判断都要能回到原文核对。

只给岗位名没给 JD → 提示需要 JD 原文，不得凭岗位名臆测内容。

### 2. Eligibility Gate（硬门槛过滤）

顺序判定：学历 → 专业 → 届数 → 外语 → 城市。事实只从档案的「硬门槛事实」取值。

**任一字段为 `[待填]` 时按 fail 处理**，输出：

```
无法完成硬门槛判定：AGENTS.md 中「<字段名>」尚未填写。
请补齐后重新执行。
```

**禁止猜测，禁止按「可能满足」放行。**

任一项 fail → 解析卡只填「基本信息」与「硬门槛」两节，写明不通过原因，**终止流程**。不打分、不生成材料。

城市为 pass/fail 不参与加权。工作形态问题（长期驻场、倒班、长期出差）不在此判定，归入「培养与稳定性」扣分。

### 3. 确认领域与方向

词典在 `template/profiles/<domain-id>/lexicon.md`，方向锚点在 `directions/<direction-id>.md`。

不确定时可先查：

```
python tools/jd_score.py --show-profile --domain <X> --direction <Y>
```

方向不属于当前领域 → 回退该领域第一个方向，并在解析卡末尾标注「结论仅供参考」。

### 4. 填写解析卡

从 `01_岗位池/_模板_解析卡.md` 复制模板。四维度打分：

- **技术匹配 30**：比对插件词典。Primary 3 分/项、Secondary 1.5 分/项。命中 Weak 不扣分，但必须登记并触发风险提示。
- **经历匹配 25**：逐条比对档案中的经验资产与 JD 职责，对上核心职责 8–10 分、侧面支撑 3–5 分、无关 0 分。**必须回查 `00_事实库/`**，不得以概述为准。
- **方向契合 30**：按方向锚点表取值。岗位名与职责不一致时以职责为准并说明依据。
- **培养与稳定性 15**：按 recruit-coach 的四分档判据。

评分依据要引用 JD 原文措辞与 `00_事实库/` 具体条目，不写空泛理由。

**证据标签（每次命中必标）**：技术匹配每一条命中，在词条后追加【精确/模糊/语义】判定依据标签，说明这条匹配是怎么判出来的：

- **精确**：JD 原文直接出现该词条或其同义词。
- **模糊**：JD 措辞与词条相近但不完全一致（如「数据挖掘」vs「数据分析」）。
- **语义**：JD 表述与词条语义等价但措辞完全不同（如「节能控制算法开发」vs 词典「控制逻辑」）。

写法示例：`- **控制 / 群控（3）【语义】**：JD"节能控制算法开发"语义等价`。旧卡无标签也能读，但新卡一律带标签以支撑前端「评分证据可追溯」下钻展示。

### 5. 校验并出结论

```
python tools/jd_score.py "<工作区>/01_岗位池/<公司>_<岗位>/解析卡.md" \
    --workspace <工作区> --domain <X> --direction <Y>
```

校验失败（退出码非 0）→ 按指出的字段修正后重跑，**不得跳过校验直接给结论**。

通过 → 把档位与下一步回填解析卡「结论」小节，并向用户输出：总分、四维度明细、档位、下一步、命中 Weak 项及桥梁话术建议。

### 6. 桥梁话术的约束

只能指向**真实可迁移能力**，并明确标注是知识性了解。**不得生成听起来像亲身经历的表述。**

## JD↔简历差距清单

解析卡通过后，可选做差距分析——它把「补关键词」拆成两类，直接服务诚实红线：

```
python tools/jd_score.py --gap --resume <版本> "<工作区>/01_岗位池/<公司>_<岗位>/解析卡.md" --workspace <工作区>
```

输出三分：

- **已覆盖（matched）**：JD 要求的词典词，当前简历版本里能直接证明
- **可召回（injectable）**：母版（`简历_主版_v1.0.md` + `00_事实库/`）里有、这一版没用上 —— **从既有事实召回即可，不构成编造**
- **真实缺口（missing）**：简历与母版都没有 —— 只能靠补真实经历，**不得靠改词硬凑**

给用户的建议措辞必须区分「召回」与「补经历」：injectable 是安全的，missing 永远不建议靠编造解决。Web 端岗位详情页有同样的差距面板。

## 输出要求

不复述 JD 内容。聚焦：判了什么、为什么这么判、下一步做什么。
