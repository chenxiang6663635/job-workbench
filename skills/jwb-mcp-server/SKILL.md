# MCP server 构建与维护（stdio 形态）

设计参照：MCP 官方规范，以及 Anthropic 的 mcp-builder 技能所倡导的工程思路。
（该仓库未声明开源许可，本文件为独立撰写，不复制其文本；思路层面的对齐是刻意的。）

## 硬性纪律（每条都对应真实事故）

- **stdout 是协议通道**：诊断一律走 stderr——一个 print 就能破坏整个会话；
- **越界拒绝**：宿主可能由模型代传参数——工作区解析 `realpath` 后校验在允许根
  之内，越界**拒绝**而不是警告（少了这道检查等于给出任意目录的读写能力）；
- **只读优先**：只读与写工具分开；写工具一律两段式（preview 拿令牌 → apply
  落盘），且「必须先给用户看过」这一步**放在协议里**（令牌的一次性 / 期限 /
  绑定），不靠提示词约束——模型看一遍摘要就调 apply 的成本几乎为零；
- **返回规范数据**：底层工具返回 dict（可脱离 SDK 单测），序列化集中在 server
  层；工具层把「拒绝」表达为 `ok:false` + 可读理由，而不是抛栈。

## 工具设计

| 维度 | 做法 |
|---|---|
| 命名 | 动词_名词 + 服务前缀（如 list_applications / preview_import_applications） |
| 描述 | docstring 写清三步用法：预览 → 把 diff 展示给用户 → 用户确认后 apply |
| 口径 | 与 CLI / 网页端**同源**：复用领域函数，不另写判据；有意差异必须注释说明 |
| 返回体 | 控制体积：列表给上限 + total；「摘要」类是完整视图的子集，不是搬家 |
| 错误 | 令牌不可用 / 冲突 → ok:false + 理由（宿主能自行决定「重新预览」） |

## 可测试性（不依赖宿主）

- 工具层与 SDK 分离：工具是普通函数、返回 dict——可直接单测；
- 两条测试线：① 造真实工作区跑口径（数据真落盘、断言真字节；mock 掉调用等于
  什么都没测）；② stdio 冒烟：真起子进程，走真通道——initialize、列出工具、
  调用工具三步全走一遍；
- 令牌目录在测试里挪进临时目录——不碰真实临时目录，用例之间不互相看见。

## 分发形态

- 独立小包（依赖集与主干互斥时优先）；`[project.scripts]` 提供命令入口；
- 宿主配置样板写进 README（command / args / type: stdio），并写明工作区解析
  优先级（参数 > 环境变量 > 默认）与「仓库需在侧」的前提；
- 语义化版本只在有实际兼容影响时动；editable 安装的前提写清楚（领域层未抽包
  之前，完全独立分发不成立）。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| stdout 打日志 | 协议会话损坏、宿主报解析错 | 日志走 stderr |
| 写工具直接落盘 | 模型可绕过用户确认 | 两段式令牌 |
| 参数直接拼路径 | 任意目录读写 | realpath + 允许根校验 |
| 返回体巨型列表 | 撑爆宿主上下文 | 上限 + total |
| 与 CLI 各写一套判据 | 同一数据两种结论 | 复用领域函数并注释差异 |
