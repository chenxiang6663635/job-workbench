# 岗位评估与材料纪律

## 核心原则

**判断由 AI 做，脚本只做 IO 与校验。** 评分不是 Python 算出来的，是你读 JD 原文与用户档案后填进解析卡的；`jobws jd` 只校验加总自洽并套阈值。改评分标准不用改代码，只改领域插件。

**唯一事实源是用户的 `00_事实库/`。** 简历动词、行为故事、经历匹配打分都必须回查事实卡，不得以解析卡概述或档案摘要为准。

## 领域插件

配置位于领域插件目录 `profiles/<domain-id>/`：

- `lexicon.md` —— 三级词典（Primary / Secondary / Weak）
- `directions/<direction-id>.md` —— 方向锚点表 + 方向特有词

通过 `--domain` 与 `--direction` 定位。插件只被读取，永不被脚本写入。

**方向不属于当前领域时**，回退该领域的第一个方向，并在解析卡末尾追加：

```
⚠️ 该岗位不属于当前领域的预设方向，评分基于 <方向> 配置计算，结论仅供参考。
```

## 流程：先过滤，再打分

Eligibility Gate **明确不通过** → **不打分、不写材料**，直接输出「不建议投递 + 原因」并终止。

判定顺序：学历 → 专业 → 届数 → 英语 → 城市。事实取自用户档案的「硬门槛事实」小节。

**字段为 `[待填]` → 结论写「待补档案」，不终止**：显式提示「请补齐档案中的 X 字段」，解析卡「硬门槛」节登记 `缺失字段: …`，**仍不打分、不生成材料**——补齐后重新评分即可。禁止猜测，禁止按「可能满足」放行；「待补档案」不是放行，是把一次判定拆成两步，判定权在补完档案之后。

城市拆两级：**硬性不可行**（要求本地户籍、必须长期驻外、明确不接受异地）→ 不通过并终止；**偏好类**（"本地优先""周边亦可""可接受搬家"）→ 不判 fail，在「培养与稳定性」扣分（轻度 -3、较强 -5，**合计不超过 5**，判据见 `references/scoring.md`）。工作形态问题（长期驻场、倒班、长期出差）不在此判定，同样归该维度扣分。

## 评分：四维度与阈值

维度权重、培养与稳定性分档、总分档位与动作见 `references/scoring.md`（表格较长，按需读取）。四条纪律：

- **技术匹配**按插件词典比对：Primary 3 分/项、Secondary 1.5 分/项；Weak 登记不扣分但触发风险提示。
- **经历匹配**逐条比对用户的经验资产与 JD 职责，**必须回查 `00_事实库/`**。
- **方向契合**按插件的方向锚点表取值；岗位名与职责不一致时以职责为准并说明依据。
- **培养与稳定性**取代常见的「文化契合」：校招 JD 里的文化表述多为套话，从文本判断可靠度低；而是否有培养体系、是否核心岗、工作形态是否可持续，既可从文本判断、也对决策影响更大。

## 两条通用诚实红线

任何场景下都必须遵守：

1. **简历每个动词都要经得起 5–10 分钟追问。** 动词由贡献事实决定，不把「参与」一律升级为「负责」。
2. **知识缺口用诚实的桥梁回答**（说明相关能力从何迁移、正在如何补），永不编造经历。

第 2 条同样约束桥梁话术：只能指向真实可迁移能力，不得生成听起来像经历的表述。

**用户自定义的红线**在其个人档案中，执行前必须读取并一并遵守。

## 简历改写边界

多版本简历 = 1 个事实母版 + N 个派生，**只改四处**：求职方向、Profile、技能顺序、项目表述。项目事实一律不动。

生成 PDF 后必须过 ATS 校验（页数 = 1、可提取文本、关键事实存在性），任一项不通过则中止归档。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 跳过 Eligibility Gate 直接打分 | 浪费时间在不合格岗位 | 先过滤，不过则终止 |
| 用解析卡概述当事实依据 | 简历出现经不起追问的动词 | 回查 `00_事实库/` |
| 硬门槛字段缺失时猜「应该满足」 | 投递后被学历或届数卡掉 | 结论写「待补档案」并提示补齐，不猜测、不终止 |
| 命中 Weak 项后生成听起来像经历的话术 | 面试露馅 | 只说可迁移能力，明确标注是知识性了解 |
| 把 Weak 写成 Primary | 面试被追问时露馅 | 分层按"能否经得起追问"判断，不是"会不会" |
| 自动执行 `git commit` | 含隐私的仓库出现非预期提交 | 生成提交信息交用户确认 |
