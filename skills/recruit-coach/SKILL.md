# 岗位评估与材料纪律

## 核心原则

**判断由 AI 做，脚本只做 IO 与校验。** 评分不是 Python 算出来的，是你读 JD 原文与用户档案后填进解析卡的；`tools/jd_score.py` 只校验加总自洽并套阈值。改评分标准不用改代码，只改 `template/profiles/` 下的插件。

**唯一事实源是用户的 `00_事实库/`。** 简历动词、行为故事、经历匹配打分都必须回查事实卡，不得以解析卡概述或档案摘要为准。

## 领域插件

配置位于 `template/profiles/<domain-id>/`：

- `lexicon.md` —— 三级词典（Primary / Secondary / Weak）
- `directions/<direction-id>.md` —— 方向锚点表 + 方向特有词

通过 `--domain` 与 `--direction` 定位。插件只被读取，永不被脚本写入。

**方向不属于当前领域时**，回退该领域的第一个方向，并在解析卡末尾追加：

```
⚠️ 该岗位不属于当前领域的预设方向，评分基于 <方向> 配置计算，结论仅供参考。
```

## 流程：先过滤，再打分

Eligibility Gate 不通过 → **不打分、不写材料**，直接输出「不建议投递 + 原因」并终止。

判定顺序：学历 → 专业 → 届数 → 英语 → 城市。事实取自用户档案的「硬门槛事实」小节。

**任一字段为 `[待填]` 时按 fail 处理**，输出中显式提示「请补齐档案中的 X 字段」。禁止猜测，禁止按「可能满足」放行。

城市为 pass/fail，不参与加权。工作形态问题（长期驻场、倒班、长期出差）不在此判定，归入「培养与稳定性」扣分。

## 评分：四维度

| 维度 | 分值 | 判据 |
|---|---:|---|
| 技术匹配 | 30 | 按插件词典比对。Primary 3 分/项，Secondary 1.5 分/项；Weak 登记不扣分但触发风险提示 |
| 经历匹配 | 25 | 逐条比对用户的经验资产与 JD 职责。对上核心职责 8–10 分，侧面支撑 3–5 分，无关 0 分。**必须回查 `00_事实库/`** |
| 方向契合 | 30 | 按插件的方向锚点表取值 |
| 培养与稳定性 | 15 | 见下表 |

**培养与稳定性（15）**

| 分值 | 判据 |
|---|---|
| 13–15 | 明确校招培养体系（导师制 / 轮岗 / 培训），岗位为技术核心岗，无强制长期驻场或倒班 |
| 9–12 | 校招岗但培养体系未明示，岗位偏技术，工作地可接受 |
| 5–8 | 培养信息缺失；岗位偏运维或现场执行；或需长期出差 |
| 0–4 | 劳务派遣 / 外包、非技术岗、强制倒班或驻场不可接受 |

本维度取代常见的「文化契合」。校招 JD 里的文化表述多为套话，从文本判断可靠度低；而是否有培养体系、是否核心岗、工作形态是否可持续，既可从文本判断，也对决策影响更大。

## 阈值与动作

| 总分 | 档位 | 动作 |
|---|---|---|
| 75–100 | 强烈建议投 | 立即生成投递包 |
| 60–74 | 建议投 | 生成投递包 |
| 45–59 | 斟酌 | 先看缺口能否一周内补 |
| 30–44 | 大概率跳过 | 除非有内推或岗位调整等额外信息 |
| 0–29 | 不投 | 终止 |

## 两条通用诚实红线

任何场景下都必须遵守：

1. **简历每个动词都要经得起 5–10 分钟追问。** 动词由贡献事实决定，不把「参与」一律升级为「负责」。
2. **知识缺口用诚实的桥梁回答**（说明相关能力从何迁移、正在如何补），永不编造经历。

第 2 条同样约束桥梁话术：只能指向真实可迁移能力，不得生成听起来像经历的表述。

**用户自定义的红线**在其个人档案中，执行前必须读取并一并遵守。

## 简历改写边界

多版本简历 = 1 个事实母版 + N 个派生，**只改四处**：求职方向、Profile、技能顺序、项目表述。项目事实一律不动。

生成 PDF 后必须过 ATS 校验（页数 = 1、可提取文本、关键事实存在性），任一项不通过则中止归档。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 跳过 Eligibility Gate 直接打分 | 浪费时间在不合格岗位 | 先过滤，不过则终止 |
| 用解析卡概述当事实依据 | 简历出现经不起追问的动词 | 回查 `00_事实库/` |
| 硬门槛字段缺失时猜「应该满足」 | 投递后被学历或届数卡掉 | 按 fail 处理并提示补齐 |
| 命中 Weak 项后生成听起来像经历的话术 | 面试露馅 | 只说可迁移能力，明确标注是知识性了解 |
| 把 Weak 写成 Primary | 面试被追问时露馅 | 分层按"能否经得起追问"判断，不是"会不会" |
| 自动执行 `git commit` | 含隐私的仓库出现非预期提交 | 生成提交信息交用户确认 |
