# 方向：数据工程

评分共用一套权重（技术匹配 30 / 经历匹配 25 / 方向契合 30 / 培养与稳定性 15），本文件只定义**方向特有补充词**与**方向契合锚点表**。

共用词典见 `../lexicon.md`。

---

## 一、方向特有补充词

### Secondary 补充

ETL、数据管道、数据建模、数据仓库、维度建模
Spark、Flink、Hadoop、Hive、MapReduce
流处理、批处理、实时计算、窗口、状态管理
数据质量、数据血缘、元数据、数据治理
Pandas、NumPy、数据清洗、特征工程
OLAP、ClickHouse、Doris、列式存储

### Weak 补充

PB 级数据平台建设、数据中台架构
机器学习建模、深度学习、推荐系统算法
数据湖与湖仓一体生产落地

## 二、方向契合锚点表（30 分）

| 岗位类型 | 分值 | 说明 |
|---|---:|---|
| 数据工程 / 大数据开发 | 25–30 | 主线岗位，直接对口 |
| 数据仓库 / BI 开发 | 22–28 | 高度相关 |
| 数据分析 | 18–24 | 相关，但偏业务解读而非工程 |
| 后端开发（含数据管道职责） | 18–24 | 部分能力可迁移 |
| 机器学习工程 | 15–22 | 相关，需确认工程与算法占比 |
| 算法研究 | 8–14 | 偏研究，工程成分少 |
| 非技术岗 | 0–8 | 基本不匹配 |

岗位名称与职责不一致时，**以职责为准**并在解析卡说明判断依据。

若 JD 实质是后端开发，应改用 `backend` 方向配置，而不是在本配置下打低分。
