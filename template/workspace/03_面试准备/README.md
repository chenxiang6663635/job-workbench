# 面试准备

本层回答一个问题：**"我应该怎么说"**。

## 核心方法：先表达，后补知识

不要从"把知识点学完"开始——知识是补不完的，而且学与说之间隔着一道坎。

正确顺序是：

```
事实卡（已验证的事实）
   ↓ 压缩
30–90 秒可说的答案
   ↓ 被追问
暴露漏洞
   ↓ 定点补
回到知识库查漏，再回填事实卡
```

**说错了、被问住了，才是有效的学习信号。** 顺着这个信号补的知识记得最牢。

## 子目录

| 目录 | 放什么 | 建议粒度 |
|---|---|---|
| `自我介绍/` | 30 秒 / 60 秒 / 90 秒三档成稿 | 一份母版 + 按方向派生，只换尾巴 |
| `项目表达/` | 每个项目的口述稿与问答卡 | 3 分钟口述 + 10 问压缩卡 |
| `核心题库/` | 高频通用题 | 控制在 60 题以内，重质不重量 |
| `行为面/` | 行为故事库 | 用 STAR+Reflection，5–6 个故事覆盖多数问题 |
| `技术面/` | 分专题的技术问答 | 按你所在领域的技术栈分专题 |
| `模拟复盘/` | 模拟面试记录与复盘 | 录音后标注漏洞，回填事实与知识 |

## 几条纪律

**控制总量。** 60 题 × 70% 能脱稿，远胜 180 题 × 看过答案。行为面建故事库，不要做「20 题 × 20 个故事」。

**自我介绍按方向派生。** 写一份 90 秒母版，各方向只改结尾的求职动机，不要每个方向重写一遍——改多了容易前后不一致。

**项目表达要能接追问。** 每个项目准备「3 分钟口述 + 10 个最可能被问的问题」。被问住的地方记进 `模拟复盘/`。

**行为故事用 STAR+Reflection。** 讲清情境、任务、行动、结果，再加一段反思——反思是区分"背模板"和"真经历过"的地方。

## 与知识库的关系

本层放**表达**，知识库放**知识**。

日常训练从本层开始；只有说错了、被追问超出现有表达时，才回 `../04_知识库/` 查。不要反过来——从知识库开始容易陷进去，且产出的是知识而不是表达。
