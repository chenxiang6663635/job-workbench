# 投递追踪

一张 CSV 管全部投递，加上每次投递的归档目录。

## 文件

| 文件 | 说明 |
|---|---|
| `tracker.csv` | 追踪表。首次 `tracker.py add` 时自动创建，不要手工编辑 |
| `_示例_tracker.csv` | **仅用于查看字段长什么样**，可随时删除。脚本不会读它 |
| `看板.md` | `report.py` 生成的漏斗看板，每次运行覆盖 |
| `applications/<公司>_<岗位>/` | 每次投递归档 |

## 字段

| # | 字段 | 取值 | 说明 |
|---:|---|---|---|
| 1 | id | `A001` 起递增 | 不复用，删除记录也不回填 |
| 2 | 公司 | 文本 | 不可改 |
| 3 | 岗位 | 文本 | 不可改 |
| 4 | 方向 | 插件 `directions/` 下的方向 ID | 由插件决定，不在脚本写死 |
| 5 | 批次 | 提前批 / 正式批 / 补录 | 校招三批并行，同一公司不同批次可能都能投 |
| 6 | 来源 | 应届生求职网 / 牛客 / 企业校招官网 / 学校就业网 / 内推 / 其他 | |
| 7 | 截止日期 | YYYY-MM-DD | 空表示未知 |
| 8 | 投递日期 | YYYY-MM-DD | 未投则空 |
| 9 | 当前阶段 | 见下 | |
| 10 | 下次动作 | 文本 | |
| 11 | 下次动作日期 | YYYY-MM-DD | 驱动「近 7 天待办」 |
| 12 | 简历版本 | 与 `resume_<版本>.html` 对应 | |
| 13 | 评分 | 0–100 | 来自 JD 解析 |
| 14 | 归档目录 | 相对路径 | |
| 15 | 备注 | 文本 | |

### 阶段枚举

正常流转：`待投 → 已投 → 笔试 → 一面 → 二面 → 三面 → HR面 → offer → 签约`

终态：`已挂` / `已放弃`

终态记录在列表中排在最后，不计入「近 7 天待办」。

## 归档目录的作用

每次投递在 `applications/<公司>_<岗位>/` 下存三样：

- `JD原文.md` —— 投递时的 JD 快照
- `简历_投递版_<YYYYMMDD>.pdf` —— 本次实际投出去的版本
- `面试记录.md` —— 面试后填写，含被问的问题与答得不好的点

有了它，三个月后能回答两个问题：**"我投这家时用的是哪版简历"** 和 **"当时的 JD 到底怎么写的"**。

JD 会改、简历会迭代、记忆会模糊——归档是对抗这三者的唯一办法。

## 常用命令

```
python tools/tracker.py list --due-within 7     # 最近七天要处理什么
python tools/tracker.py update --id A001 --stage 一面 --next "准备口述" --next-date 2026-09-10
python tools/report.py                          # 生成看板
```

`update` 只能改阶段、下次动作、日期、备注、评分。**公司与岗位不可改**——需要改则新建一条，把旧的标为已放弃。
