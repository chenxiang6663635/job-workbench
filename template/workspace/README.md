# 工作区骨架

本目录是空的工作区骨架。运行 `python tools/init_workspace.py` 会把本目录复制到 `personal/`，然后你在 `personal/` 里填自己的内容。

六个模块的用途与填写要求：

## 00_事实库 —— 唯一事实源

放你的项目事实卡、实习事实卡。

**为什么必须单独一层**：简历动词、行为故事、JD 评分的「经历匹配」维度都要回查这里。没有它，AI 只能凭解析卡概述写材料，就会出现经不起追问的动词。

每张事实卡写清：做了什么、你的个人贡献边界、可验证的数字或证据、不能越界的说法。

## 01_岗位池 —— 每个岗位一个目录

```
01_岗位池/<公司>_<岗位>/
├── JD原文.md      # 完整原文，不改写不摘要
└── 解析卡.md      # 硬门槛判定 + 四维度评分
```

保留 JD 原文的理由：所有判断都要能回到原文核对，且能回答「三个月前投这家时 JD 怎么写的」。

## 02_简历工坊 —— 简历与 PDF

- `简历_主版.md`：事实母版，不投递
- `简历_<方向>.md`：各方向派生版
- `pdf/resume_*.html`：PDF 生成源
- `pdf/photo.jpg`：一寸照

**PDF 生成源是 HTML 不是 Markdown**，改简历必须同步改 HTML。

## 03_面试准备 —— 表达训练材料

自我介绍、项目表达、核心题库、行为面、技术面、模拟复盘。

组织原则：把事实压缩成 30–90 秒可说的答案，然后被追问、暴露漏洞、回来补知识。先有表达，再补知识，不要反向堆知识点。

## 04_知识库 —— 按需查阅

放知识词典、技术速查卡。

**日常训练不要从这里开始。** 只有说错了、被追问超出现有表达时，才回来翻。

## 05_投递追踪 —— 一张 CSV + 归档

- `tracker.csv`：所有投递记录，UTF-8 with BOM（Excel 直开不乱码）
- `applications/<公司>_<岗位>/`：每次投递的 JD 快照、当次简历 PDF、面试记录

归档的意义：能回答「三个月前投这家时用的是哪版简历」。

## 关于 99_归档

历史文件与不再维护的脚本放这里，只增不改。历史文档中的旧目录名不做改写——如实记录当时状态才是它的价值。
